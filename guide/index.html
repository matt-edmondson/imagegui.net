ImageGui user guide

This guide walks through ImageGui by task: opening an image, adjusting it, working with layers, text, and shapes, selecting and masking, painting, retouching, changing its geometry, checking it for accessibility, exporting it, taking it to and from Blender and Godot, and keeping its versions, in git or without it. The images come from the feature gallery, which the test harness takes screenshots of the running application on every build of main, so they show the shell as it is today.

Every edit in ImageGui is non-destructive. Adjustments, crops, turns, and masks are recorded as steps on top of your original files, which are never changed, and every step can be undone, edited later, or switched off.

Getting started

The first time ImageGui starts, the start screen offers a five-step tour. It outlines the tool strip, the Layers panel, the inspector, History, and the File menu’s Export in turn, with a callout beside each saying what it’s for. Next and Back move between the steps, Skip tour closes it at any step, and Help > Take the Tour starts it again whenever you like. Started with nothing open, it opens the sample project first, so every part it points at is on screen.

Help > Open Sample Project, also on the start screen, opens a small poster built to show the main features at once: an image of hills at sunrise under a curve, vibrance, color grading, and a vignette; a cloud texture graph screened over the sky and masked away toward the horizon; a banner shape with a drop shadow and a stroke; a caption whose first word is set in a run of its own; and two artboards, one wide and one square. Select any layer to see how it was made. The sample opens untitled, carries its image inside it, and is only saved if you save it.

Opening images and projects

File > Open (Ctrl+O) opens a PNG, JPEG, WebP, TIFF, OpenEXR, GIF, BMP, or ICO image, a camera raw photo (see Raw photos), a Photoshop file (.psd or .psb), or an .imagegui project. You can also name one when starting ImageGui (ImageGui photo.jpg). With nothing open, the canvas shows a start screen in its middle: New, Open, a reminder that you can drop files onto the window, a button that opens the sample project, and your recent files as a grid of thumbnails with each file’s name and folder under it.

File > New (Ctrl+N) makes a blank canvas: type a size or pick one of the screen, print, and square presets, over white, black, a color, or nothing at all, working in Linear sRGB or ACEScg (see Working in ACES). A colored background is an ordinary fill layer named Background, so it can be recolored or deleted later.

TIFF files from scanners and other editors open whether uncompressed or LZW, Deflate, or PackBits compressed, at 8 or 16 bits, in color or grayscale, with or without transparency.

Photoshop files open with their layers: names, groups and pass-through, visibility, opacity, clipping, blend modes, and layer masks all come across, and each layer’s pixels are kept inside the project. Text, smart objects, and fill layers arrive as the pixels Photoshop last drew for them, renamed to say so. An Invert, Levels, or Exposure adjustment layer becomes the same adjustment here; other adjustment layers are left out. A file with 16 or 32 bits a channel comes across with 8, and the list says so. Whatever didn’t come across exactly is listed once the file opens. File > Place takes a Photoshop file too, and adds its layers as one group.

OpenEXR files from renderers and compositors open with their full range: a highlight brighter than white stays brighter than white, so an Exposure adjustment can bring it back down rather than finding it clipped. An OpenEXR file opened on its own makes a document that works in ACEScg, which keeps every value; files in ACES2065-1 or ACEScg are converted to it as they open. File > Place takes them too. Placed in a document that works in linear sRGB, which clips everything above white wherever it blends, adjusts, or exports, a file with brighter values says so once. A file compressed in a way ImageGui doesn’t read, such as DWAA or B44, is refused with a message saying so. A render saved with its passes opens as layers; see Working with Blender.

An animated GIF or WebP opens at its first frame, and a TIFF file at its first page. File > Open as Layers opens every frame, or every page, as a layer of its own, the first at the bottom, with a layer comp for each that shows it alone and remembers how long the frame shows. File > Export Animation then makes a frame of each comp at its own timing, so an edited animation goes back out as it came in.

Edit > Paste as New Layer (Ctrl+V) adds the image on the system clipboard as a layer at its own size, in the middle of the canvas, or opens it as a new image when nothing is open. Edit > Copy Merged puts what the canvas shows on the clipboard, every layer together, cut to the selection when there is one.

Images dragged from your file manager onto the canvas become new layers, centered where you drop them, and several dropped at once are one undo step. With nothing open, or with Shift held, a dropped image or project opens instead, asking first about unsaved changes.

Photos open the way they were taken: an image the camera stored sideways is turned upright, and a wide-gamut color profile such as Display P3 is converted to sRGB.

File > Open Recent lists recent files with a thumbnail of each one beside it. A project carries its own; an image is decoded small for one.

A project links to its original images rather than copying them. If one has moved, ImageGui asks where it went, or opens the project without it so you can point the layer at its file later with Layer > Relink Image. Once one file is found, others from the same folder are offered too.

If ImageGui stops without saving, the next start offers your unsaved work back.

If ImageGui ever closes because of an error, it also writes a report to a dated file in its data folder (Logs in the folder Preferences names, beside the log file): the error, the versions in use, the image’s size and layer count, and the names of the last steps you took. It holds no pixels and no folder names, and nothing is ever sent anywhere. The next launch says so once and offers to open the folder or copy the report, so you can share it if you want to report the problem.

ImageGui starts on the start screen. To pick up where you left off instead, choose Reopen what was open under On launch in Preferences: the project or image that was open when ImageGui last closed opens again at the zoom and scroll you left it at. A file named when starting ImageGui, or one opened from the file manager, comes first, and unsaved work from a crash is offered back as above rather than reopened silently.

Raw photos

File > Open, File > Place, dropping a file, and Batch all read camera raw files: DNG, Canon CR2 and CR3, Nikon NEF, Sony ARW, Fujifilm RAF, Olympus ORF, Panasonic RW2, and Pentax PEF. A raw photo opened on its own makes a document that works in ACEScg, so nothing the sensor recorded is clipped. Placed in a document that works in linear sRGB, a photo brighter than white says so once, as an OpenEXR file does.

A raw photo stays raw. The layer keeps the camera’s data, and the inspector’s Raw section, above the adjustments, develops it again whenever you change a setting: a quick draft first, then in full a moment later. Every change is a step in the history, and a slider drag is one step, so trying a setting costs nothing.

  • White Balance is As Shot, the white the camera recorded; a kind of light (Daylight, Cloudy, Shade, Tungsten, Fluorescent, or Flash); or Custom.
  • Temperature and Tint always show the white the photo is balanced to, whichever choice made it, so you can start from a preset and fine-tune it. Moving either makes the white balance Custom. A higher temperature makes the image warmer, and a positive tint makes it more magenta. The numbers mean what they mean in other raw developers.
  • The pick button beside White Balance sets the temperature and tint from a spot on the canvas that should be gray or white. Click it, then click the spot; Esc cancels. It measures the photo itself, so adjustments and layers above it don’t change what it picks.
  • Highlights is Clip, which turns anything the sensor couldn’t hold into a clean white, or Reconstruct, which fills in a blown channel from the ones that weren’t, so a bright sky keeps some color.
  • Detail is Full, the careful demosaic, or Draft, a fast and softer one.

Under them are the camera, lens, and exposure, and the Info panel lists them with the date the photo was taken. Exports wait for a raw layer to finish developing, so a file never goes out with the quick draft.

Looking at the image

View > Zoom In (Ctrl+=) and Zoom Out (Ctrl+-) step through fixed scales; Fit, 50%, 100%, and 200% jump straight to one. Scrolling over the canvas zooms too.

The status bar under the canvas shows the image’s name, with a * while it has unsaved changes, its size in pixels, the zoom, the pointer’s position in the image’s own pixels, the git branch when the project is in a repository (see Committing a project), and a one-line hint for the chosen tool. Click the zoom for a list of presets, or type a percentage such as 150 and press Enter.

While you work, the canvas shows a preview of the image held to the Preview size set in Preferences, so edits stay quick on large images. Zoomed in past that preview’s own pixels, the canvas renders just the part you can see at the screen’s scale, up to the image’s own pixels, as soon as you stop panning or zooming. While you drag, the last render stays where it belongs and the enlarged preview fills in around it. A few adjustments, such as lens correction, need the whole image to render any part of it; on an image too large to render whole at that size, the canvas keeps the enlarged preview and shows a Preview badge in its corner. Exports always use the full image.

From 600% each pixel is drawn as a flat square, and View > Show Pixel Grid draws a line around each. With View > Pixel Art Display on, pixels are flat squares from just above 100%; see Making game assets.

The View menu also opens these panels:

  • Navigator: the whole image small, with a rectangle you drag to pan.
  • Info: the position and color under the pointer, and while you edit an adjustment, the color entering and leaving it.
  • Histogram: the finished image’s histogram, per channel or luminance, with clipping, for the whole image or the selection only. Pick the channel from the tabs along its top, as in levels and curves. The graph grows with the window, so drag its edge for a larger one.
  • Show Clipping (Shift+J): tints the canvas where the image has clipped, blue where every channel is black and red where any channel is at white. It only marks the screen, never the image, and follows drags live. Clicking either clipping readout in the histogram turns it on or off, and Preferences can widen its thresholds to warn of pixels that are nearly clipped.
  • Show Accessibility Issues: outlines in red the text and shapes that fail the contrast check. See Checking accessibility.
  • History: every edit by name (see Undo and history).
  • Before/After: compare with the image before its adjustments and effects, alone, side by side, or split by a divider. Backslash (\) toggles it.
  • Onion Skin: while you draw an animation, show the frame before the current one tinted red and the frame after it tinted blue, wherever they differ from it, at an opacity you choose. Alt+, and Alt+. step back and forward a frame. See Exporting an animation.
  • Rotate View (R): turn the canvas on screen, as a painter turns the paper, without changing the image. Drag round the canvas to turn it; hold Shift to turn in 15° steps. Double-click or press Esc to put it upright, or choose Reset Rotation. The status bar’s zoom shows the angle, and every tool, guide, and readout follows the turn.
  • Proof: show the canvas as seen with protanopia, deuteranopia, or tritanopia, at a severity you choose, as grayscale, or blurred as someone with low vision sees it. It changes only what the canvas shows: a badge marks it while it’s on, and exports are untouched. See Checking accessibility.
  • Rulers: pixel rulers to drag guides out of. Dragged layers snap to guides, and Snap turns snapping off.
  • Trim Sheet Strips: name the strips the horizontal guides cut the image into, see their UVs, and export them. See Laying out a trim sheet.

Panels open as tabs beside Layers in the right column, never over the canvas: History, Histogram, Navigator, Info, Layer Comps, Text Styles, Notes, Artboards and Versions. The View menu checks the ones that are open. Drag a tab to dock it above, below or beside another panel, or out of the column to float it. ImageGui remembers where each panel is, and View > Reset Panel Layout puts them all back as tabs beside Layers. Liquify’s and Refine Edge’s options open inside the canvas’s right edge, clear of the panels.

Drag the gap between the canvas and the right column to make the column wider or narrower, and the gap between the panels and the inspector to give either more height. ImageGui remembers both, and double-clicking a gap puts it back where it started. Until you drag it, the gap under the panels follows the Layers panel’s rows.

Working in ACES

An image works in one of two spaces. Linear sRGB, the default, is how every image has always worked: display light, with anything brighter than white clipped where tones are shaped. ACEScg is the ACES working space that film, visual effects and game studios share: scene light, where a highlight keeps its value however far above white it is, shown through an output transform (see Viewing through ACES).

Image > Color Management chooses the working space, and for an ACEScg image the display and view it is shown through. Changing the working space converts every color the image stores, in paint strokes, fill colors and gradients, shapes, text and character styles, layer effects, Photo Filter and Gradient Map, so the image keeps its colors. The whole change is one step in the history. Curves, Levels and Blend If keep their points as they are: in an ACEScg image they work on ACEScct, the grading encoding, rather than on sRGB. File > New can make an ACEScg image from the start, and remembers the space last chosen.

In an ACEScg image, the inspector shows each image layer’s Input Transform, which says what its pixels are:

  • sRGB Texture, for photos and 8-bit images. Converting an image to ACEScg gives its 8-bit layers this one.
  • Inverse Output Transform, for logos, interface art and graphics that must look on screen exactly as they were drawn.
  • ACES2065-1, ACEScg and Linear Rec.709, for float files such as EXRs.

Color fields still show and take sRGB colors, as a picker always does, and the swatches and recent colors are the same ones every image shares. Their popup adds the ACEScg values the image stores, where a light brighter than white is typed as a value above 1. Picking a color from the canvas takes the working value under the pointer as it is.

Viewing through ACES

An ACEScg document holds scene light, where a highlight can be many times brighter than white, and is shown through an ACES output transform that fits it to the screen. View > View Transform picks how:

  • ACES 2.0 SDR, the default, rolls highlights off smoothly and brings saturated colors into the display’s gamut, the way a grading suite shows ACES footage.
  • Un-tone-mapped converts the working values to the display without tone mapping, so anything above 1 clips. Use it to check what the pixels actually hold.

View > Display picks the screen the image is fitted to: sRGB for an ordinary computer screen, Display P3 for a wide-gamut screen set to that mode, or Rec.709 for video at gamma 2.4. Both choices are saved with the document and are one step in the history, so Ctrl+Z puts the last one back.

Everything that shows the image goes through the same output: the canvas, the second view, thumbnails, the Histogram, the clipping overlay, the accessibility checks, and Edit > Copy Merged. The Info panel and the color samplers read out what the screen shows, and Info adds an ACEScg row with the working value under the pointer, unclamped. The status bar names the working space and view, such as “ACEScg · ACES 2.0 SDR”. A linear sRGB document is shown as it is, and both submenus are unavailable for it.

Exports follow the screen. PNG, JPEG, WebP, TIFF, TGA, PDF, SVG, Photoshop and animation exports of an ACEScg document go through the same display and view the canvas shows, so the file looks like the canvas. The export options say which display and view they use. A PNG, JPEG or WebP made for Display P3 or Rec.709 carries that display’s color profile, so other programs show it correctly. Other formats carry no profile, and the options say so. The export preview, and its original, go through the same output. Export as OpenEXR to keep the scene light itself (see Exporting OpenEXR files).

A second view

Window > New View opens a second window onto the same image, so you can work close in on the canvas and watch the whole image beside it. It opens fitted to the image, floating over the canvas’s right side, and you can drag it anywhere or dock it beside a panel.

The second view has its own zoom, scroll, turn, and proof. Scroll over it to zoom, pan it as you pan the canvas, and use Fit and 100% along its top. Tick Rotate to turn it by dragging, as Rotate View turns the canvas, and pick a proof from the list beside it to proof this view alone, so the canvas can show the image as it is next to it. Zoomed in past the preview, it renders its own part of the image at full resolution, just as the canvas does.

Both views show one image with one history, so every edit shows in both. The tools work in whichever view has focus: click in the second view to select, paint, or move there, and click back on the canvas to work there again. The other view keeps showing the selection. Window > Close View, or the window’s close button, closes it, and nothing is lost.

Color samplers

A color sampler is a point on the image whose color stays on show while you work. Press I twice to choose the Sampler (the first press is the Measure tool). A click with it picks the color under the pointer into your recent colors; Shift-click pins a sampler there instead, up to eight. Each is a numbered target. Drag one to move it, and Alt-click it to delete it.

The Info panel lists the samplers under Samplers, each with a swatch and its value as RGB, hex, HSL, or Oklch, whichever you choose above the list. A value follows a drag live from the preview, then is read again from the full-size image once the preview settles, and its tooltip says which you are looking at. A sampler reads the composite unless you choose one layer for it in its row; it then reads that layer with its own adjustments, but without the layers above it. The Sampler’s options can make new samplers read the selected layer, and clear them all.

Curves and Levels mark where each sampler’s color enters them, one line per channel on the RGB tab, so you can see which part of the graph the color goes through. Show samplers in either editor turns the marks off. View > Show Samplers hides or shows the targets; the Sampler shows them while it is chosen. Samplers are saved with the project and move with the image through crops, turns, and Canvas Size, but they are never drawn into the image.

Notes on the canvas

Notes are reminders pinned to a spot on the image, such as “fix this edge” or “client wants warmer”. Choose the Note tool (N), click where the note belongs, type it, and press Enter; Ctrl+Enter starts a new line, and Escape drops it. Each note is a numbered pin. Hover a pin to read its note, click it to edit or delete it, and drag it to move it.

View > Notes lists every note by its first line. Click one to highlight its pin and edit its text below the list. View > Show Notes hides or shows the pins; the Note tool shows them while it is chosen. Notes are saved with the project and move with the image through crops, turns, and Canvas Size, but they are never drawn into the image, so no export has them in it.

Checking accessibility

ImageGui checks whether the images you make can be seen and read by everyone who will look at them. The checks never stop you saving or exporting anything; they say what they found and leave the choice to you.

The Accessibility panel

View > Accessibility opens a panel, docked beside Layers like Histogram and Info, that checks the image while it is open. Nothing runs while it is closed. The checks read the image the canvas shows, so opacity, blend modes, effects, adjustments above a layer and the photo behind it all count, and they run again whenever the image changes.

At the top, choose the level the image is held to. AA asks 4.5:1 contrast for text and 3:1 for large text, which is what most sites and laws ask for; AAA asks 7:1 and 4.5:1. Display scale says how big the image is shown: 2x for an image made at twice the size it appears, as for high-density screens, so a 40-pixel heading counts as the 20 pixels a reader sees. It is the same setting as the one under View > Proof. Text is large from 24 CSS pixels, or 18.66 if it is bold. Smallest text is the size below which text is reported as too small to read whatever its contrast. The level and the display scale are saved with the document; the smallest size is a preference.

Under them are the image’s description, the alt text a screen reader reads out, and an optional long description for everything a sighted reader gets from it, such as a chart’s numbers. Each is one history entry when you leave the field. Text in the image that the description doesn’t repeat is listed under the fields, since a screen reader can’t read it from the pixels, and Add to Description adds it to the end.

Every export carries the description in the file, where screen readers, content management systems, and search engines look for it: the XMP metadata of a PNG, JPEG, WebP, TIFF, or PDF (as the IPTC alt text and extended description fields), a TIFF’s image description, a PDF’s subject, and an SVG’s title and description. An artboard with a description of its own carries that one instead. GIF has nowhere a reader looks, so a GIF carries none. With no description, the file is exactly what it would have been.

The findings come in three groups:

  • Text: each visible text layer, with the color it is drawn in and what is behind it where it reads worst, its lowest contrast, whether it is normal or large, and a pass or a fail. A note under the name says when the text is too small, or when it passes for most people but is hard to read with protanopia, deuteranopia, or tritanopia. Fix sets the text’s color to the nearest one that passes against what is behind it, keeping its hue where it can, and colors set on parts of the text are fixed too. It is an ordinary edit, named “Text color” in History, so Undo takes it back.
  • Graphics: each visible shape layer, held to 3:1 against what is behind it, measured on its stroke if it has one and its fill if not.
  • Colors: pairs of shape, text, and fill colors that most people tell apart but that look alike with a color vision deficiency. Don’t let color alone tell them apart; add a label or a pattern.

Hover a row to outline the parts of the layer that were measured on the canvas, failing parts in red, and click it to select the layer. Ignore leaves a layer out of the checks, for decoration that needs no contrast; the document remembers it, and Include all brings every ignored layer back.

The checks read the preview, which is quick but can be too coarse for small text. Check at Full Size renders each layer’s surroundings at the document’s own size instead, with progress and a Cancel button. The panel says which of the two its numbers came from, and goes back to the preview when the image changes.

Describing an image as you export it

Export, Export Layers, Export Animation, and Export As Set each have a Description field above their format choice, so you can write the alt text when you are about to publish rather than remembering to open the Accessibility panel first. It is the same description the panel edits: typing there changes the document, it is one history entry named “Edit Description” when you leave the field, and it is saved with the project. Canceling the export keeps what you typed, and Undo takes it back. The field changes the document’s description only; an artboard with one of its own still carries that.

Leaving the field empty is fine. Empty, it says “Describe the image for people who can’t see it”. If your images never go on the web, turn off Suggest a description when exporting in Preferences > General and the field stays blank.

Showing issues on the canvas

View > Show Accessibility Issues outlines in red every part of the image’s text and shapes that fails the contrast check, so you can see what to fix without reading through the panel. It runs the same checks as View > Accessibility, and works with the panel closed. The outlines follow a layer while you drag it, and the image is checked again once you let go, so moving text onto a darker or lighter part of the image shows straight away whether it reads there. Like the panel, it changes nothing in the image, and exports never show it.

Proofing for color vision and low vision

View > Proof shows the canvas as someone with a color vision deficiency sees it:

  • Protanopia, Deuteranopia, and Tritanopia are the missing red, green, and blue cones. The Severity slider under them sets how strong the deficiency is. At 100% it is the dichromacy; lower settings show protanomaly, deuteranomaly, and tritanomaly, which are far more common. The badge on the canvas names what you’re seeing, such as “Deuteranomaly, 60%”.
  • Grayscale shows luminance alone, as grayscale print or a monochrome display does.
  • Blurred shows the image as someone with 20/200 acuity sees it, the usual line for low vision. Small text that turns to a smudge here needs to be larger or bolder. The blur is sized for the image’s display size: if it will be shown at half its pixel size, as a 2x asset is, set Display scale under it to 2. The display scale is saved with the document, and the flash check in Export Animation reads it too.

The simulations use the Machado, Oliveira, and Fernandes (2009) model in linear light, and the blur is a Gaussian whose width at half its height is the detail 20/200 acuity just resolves. Like every proof, they change only the canvas: exports, the histogram, and the readouts see the image as it is.

Flashing in animations

Animations that flash can bring on seizures. WCAG 2.3.1 allows no more than three flashes in any one second where a flash covers a quarter or more of a reader’s central field of view, about 341 by 256 pixels on a typical screen, and counts flashes into and out of saturated red apart from changes in brightness.

Export Animation checks its frames while its options are open. It renders them small, so the check is quick, and shows one line above Export: “No flashing found”, a count that is within the limit, or, in red, how many times a second the worst second flashes and between which frames. The line follows the options as you change them: the frames, the size, the timing of every frame, and whether the animation loops, since a looping animation also changes from its last frame back to its first. A small image can’t flash, since all of it is less than a quarter of the field. Transparent pixels are judged as they would look on a white page.

Checking from the command line

The checks also run without a window, so a build or a pre-commit hook can stop a banner that has drifted below AA from going out:

ImageGui --check banner.imagegui
ImageGui --check banner.imagegui --level AAA --scale 2 --json

It opens a project or an image, renders it at full size, and prints one line for each finding, then a line counting them:

pass   Shape "Logo": 5.2:1 at worst, needs 3.0:1 (graphics)
fail   Text "Headline": 2.4:1 at worst, needs 4.5:1 (AA, normal text); 30% of it passes
advice Text "Headline": its words aren't in the description
banner.imagegui: 1 failure, 1 advice, 1 passed at AA, display scale 2

Failures are what WCAG asks for normal vision: text and shapes below the contrast their level needs, and text under 12 CSS pixels. Advice is the rest: contrast that fails only for someone with a color vision deficiency, colors that look alike to someone with one, a missing description, and text the description doesn’t repeat. Shapes are held to 3:1, normal text to 4.5:1 (7:1 at AAA), and large text to 3:1 (4.5:1 at AAA).

--level and --scale stand in for the level and display scale saved with the document; without them, the document’s own are used. Layers you’ve marked ignored stay ignored. --json prints one JSON object instead, with every finding’s layers, ratio, and the ratio it needed. Flashing isn’t checked here, since whether a document is an animation is chosen in Export Animation.

The command exits with 0 when nothing fails, 1 when anything does, and 2 when the command line couldn’t be understood or the file couldn’t be read. Advice doesn’t change the exit code unless you add --strict.

Adjusting color and tone

Select a layer and choose from Add adjustment in the inspector. Adjustments stack, and each applies to the result of the ones before it. Move one up or down with its arrow buttons, switch it off without losing its settings, or remove it. Each sits on a card of its own; the arrow at the left of its header folds it away, and folding one kind (every Curves, say) folds it on every layer and keeps it folded next time.

The inspector reads from what the layer is to what is done to it. A band at the top names the selected layer and says what kind it is: an image with its size (hover it for the file it comes from), a text or shape layer, a group and how many layers it holds, or a placed project and the file it’s linked to. Then come the layer’s own content (its text, shape or fill), its adjustments, its effects, and last Crop and straighten, which is folded until you open it.

Every slider in the inspector shows its value in the middle, with nothing drawn over it. Drag anywhere on a slider to change it, hold Shift while dragging for finer steps, and Ctrl+click it to type a value. A slider that runs either side of zero fills from zero, and double-clicking it puts it back to zero. Values read in the same units everywhere: opacities and amounts are percentages, angles and hue shifts are degrees, temperature and tint run from -100 to 100, and radii are pixels at the canvas size.

The adjustments available are exposure, brightness/contrast, saturation/vibrance, black and white, levels, curves, white balance, HSL, color balance, color grading, channel mixer, selective color, match color, sharpen, Gaussian blur, clarity, shadows/highlights, vignette, noise reduction, dehaze, lens correction, invert, posterize, threshold, gradient map, photo filter, displace, make seamless, and Graph Filter.

Levels and curves are drawn on the histogram of the pixels reaching them, as wide as the panel, and both have a tab for each color channel as well as the composite. The curve sits in a square box, so its diagonal stays at 45 degrees. Pick black point and Pick white point set levels from a click on something that should be black or white.

Levels, curves, and white balance each have an Auto button that sets them from the histogram, as one undo step you can carry on editing. White balance takes a gray-world estimate of the light, levels sets each channel’s black and white points so a tenth of a percent clips at either end, and curves draws a stretch between the darkest and brightest tenth of a percent with a gentle S.

White balance and HSL can be set by clicking on the canvas: Pick neutral point balances on something that should be gray, and Pick color on canvas finds the HSL band under the pointer, which you then drag left or right to adjust.

Color grading has a wheel each for the shadows, midtones, and highlights, and a global wheel for the whole image. Push a wheel’s handle toward the color to add; how far from the center is how strong the tint is, and the slider under the wheel brightens or darkens that range. Double-click the wheel or its slider to reset it. Blending sets how far the ranges overlap, and Balance leans them toward the shadows or the highlights.

Match Color moves a layer’s colors toward another image’s, so one shot takes on the mood of another. It matches the average and the spread of lightness and of color, so a warm, contrasty source makes the layer warm and contrasty while its image stays where it was. Pick the Source from the document’s layers, read through their adjustments (a hidden layer works too), or use Match an image file… to measure an image on disk. With a layer as the source, Measure Selection measures it only inside the canvas selection, such as a face or the sky. Luminance and Color Intensity brighten or darken and strengthen or mute the result, Fade lets the original show through, and Neutralize takes out a color cast, with or without a source.

The colors are measured once and saved in the project, and measured again whenever the source or the layer changes. So an image file isn’t needed after it’s measured, and if the source layer is deleted the adjustment keeps the colors it last measured and says so. A layer that already depends on this one can’t be picked, since matching it would go in a circle.

Channel mixer rebuilds each output channel from red, green, and blue plus a constant, on a tab per channel. Its total turns amber when a row strays from 100%, since above that the channel brightens. Monochrome mixes one gray for all three. Selective color adds or takes away cyan, magenta, yellow, and black in one family of colors at a time, from reds to blacks: Relative scales each change by the ink already there, and Absolute adds it outright.

Channel swap fills each of red, green, blue, and alpha from any one channel, from None (black, or transparent in alpha), or from Full (white, or opaque), and Invert turns a channel over. Use it to swap red and blue, see a mask by moving alpha into a color channel, use a painted channel as alpha, fill alpha so a layer is opaque, flip a normal map’s green between OpenGL and DirectX, or turn roughness into smoothness. A channel crosses into alpha, or out of it, as the value an 8-bit export writes, so 128 in red becomes 128 in alpha, and an inverted channel exports as 255 minus what it was. In an ACEScg document, where an export goes through the view, a color crosses into alpha as its linear value.

Debayer turns a gray mosaic, the image a camera sensor records before its colors are filled in, into a color image. Each pixel holds what one photosite saw through its red, green, or blue filter, and Pattern names how those filters are laid out: RGGB, BGGR, GRBG, or GBRG, named by the mosaic’s top-left two by two, or Fujifilm’s six by six X-Trans, whose Column offset and Row offset move the tile when the mosaic wasn’t cut where it starts. Method picks the detailed demosaic a raw photo is developed with, RCD for a Bayer pattern and Markesteijn for X-Trans, or Bilinear, which is faster and softer. Red gain and Blue gain multiply those photosites first, the white balance a sensor’s mosaic usually needs. The mosaic is read at its own pixels wherever the layer is placed, scaled, or turned, so the preview keeps its color at any zoom. A wrong pattern shows as swapped colors or a fine checkered pattern.

Gaussian blur softens the whole layer, so a layer’s own edge feathers out without a dark fringe. Clarity is local contrast: it pushes each pixel away from the area around it, weighted to the midtones, and dragged left it softens instead. Both measure their radius against the layer’s height, so the preview shows what the export will. The slider shows the radius in pixels at the canvas size, with the share of the layer’s height it stands for underneath.

Shadows/highlights opens up dark areas and recovers light ones. How much each pixel moves depends on how dark or light the area around it is, not on the pixel alone, so a shadow lifts while the texture inside it keeps its contrast, and black and white stay where they are. Shadows and Highlights set the two amounts, Tonal width how far from black or white an area still counts as shadow or highlight, and Radius how wide an area each pixel looks at. Color correction strengthens the color of what moved, or mutes it when dragged left, and Midtone contrast steepens or flattens the middle of the range. At its defaults it changes nothing.

Noise reduction smooths grain in lightness while keeping edges, and Detail puts some texture back; Color smooths color blotches. Dehaze takes out haze, clearing distant hills and deepening the sky; dragged left, it adds haze instead.

Lens correction removes barrel or pincushion distortion, the red/cyan and blue/yellow fringes toward the corners, and the darkening a lens leaves in them, centered on the layer. Correcting barrel distortion pulls the middle of each side in and leaves transparent edges; Auto Scale enlarges the image just enough to crop them away.

Make seamless blends an image’s opposite edges into each other so it tiles without a visible seam, for textures, patterns and backgrounds. Each edge is mixed with the image’s own middle, which is what sits across the join once the image repeats, so the joins disappear and everything further in than Blend width stays exactly as it was. A wider blend hides a strong seam better; a narrower one leaves more of the image untouched. Across and Down choose which pair of edges is blended, and the Tiled preview shows the result with its joins in the middle, repeated along the edges you blend. It repeats the layer’s own frame, which for an image filling the canvas is the canvas. Mask it like any adjustment to keep something near an edge, and lower its opacity to blend less.

Fading and blending an adjustment

Under each adjustment’s name are its Blend mode and its Opacity. Lowering the opacity fades the adjustment toward the pixels it was given, so a black and white at 60% leaves some color in. A blend mode combines the adjustment’s result with its input the way a layer’s mode combines it with what is below: Luminosity changes brightness without shifting color, Color changes color and keeps brightness, and a neutral adjustment in Multiply, Screen, or Soft Light darkens, lightens, or adds contrast on its own. A mask has only an opacity, which fades how much of it applies.

Reusing adjustments

Edit > Copy Adjustments (Ctrl+Shift+C) copies the selected layer’s stack, and the copy button on an adjustment copies just that one. Paste Adjustments (Ctrl+Shift+V) adds them to every selected layer.

To keep a stack for later, or for other images, save it with Layer > Presets > Save Stack as Preset, or right-click one adjustment and Save as Preset. Presets apply from the same menu or from the inspector’s Presets list. Saving a whole stack can include the layer’s effects too; applying such a preset replaces each layer’s effects with them.

Layers

A document is a tree of layers and groups, listed top first in the Layers panel. Click a row to select it, Ctrl+click to select several, double-click to rename, and drag to reorder or drop into a group. Every panel acts on the selected layer.

The eye at the start of a row hides or shows the layer. Text layers show a letter where the thumbnail would be, an empty group shows a folder, and shape, fill and paint layers carry a star, a drop or a brush in the thumbnail’s corner. A layer in a group sits one step to the right of the group, and the arrow beside a group that holds something folds it away. A padlock shows at the right end of a locked layer’s row, and faintly on any row the pointer is over. The icons under the rows add an image, a group, or text, add an adjustment or an effect to the selected layer, or delete the selection; hover one for its name. The panel is as tall as its rows need, up to a little over half the column. While another panel’s tab is in front of Layers, the column gives it at least a third of its height. Dragging the gap under it keeps it at the height you choose, and ImageGui remembers that height.

From the Layer menu, which groups its commands into submenus:

  • New adds a layer: Image Layer places another image on the canvas, Text Layer (Ctrl+Shift+T) adds text, Fill Layer adds a solid color, a gradient, a pattern or a texture graph, Shape adds a shape in the middle of the image, Paint Layer an empty layer to paint color on (see Painting), and Group (Ctrl+Shift+N) an empty group. Artboard is there too.
  • Duplicate (Ctrl+J) and Delete (Delete) sit at the top of the menu.
  • Arrange holds Move Up (Ctrl+]) and Move Down (Ctrl+[), Align and Distribute, which line layers up with the canvas or each other, and Link Layers and Unlink Layers.
  • Combine holds Group (Ctrl+G) and Ungroup (Ctrl+Shift+G), Clip to Layer Below (Ctrl+Alt+G), which shows a layer only where the one beneath it is, and Merge Down, Combine Shapes and Flatten Image. Ungrouping keeps the image: the group’s position, perspective, and visibility go onto each layer in it, and a group holding one layer hands that layer its blend mode, opacity, effects, and adjustments too. When something can’t be moved exactly, such as a mesh warp or an adjustment over several layers, Ungroup is unavailable and its tooltip says what would be lost.
  • Adjustments, Effects and Presets offer what the inspector’s Add menus and Presets list do.

  • Rasterize turns a text or paint layer into an image layer that looks the same, Combine > Merge Down (Ctrl+E) merges a layer into the one beneath it, and Flatten Image leaves one layer of what the canvas shows. The result’s pixels are kept inside the project, and undo brings back the layers they replaced. The first time, each says what it will lose before it runs: anything reaching past the canvas, hidden layers, and color finer than 8 bits a channel, since the new layer is stored that way. Don’t ask again stops the question; File > Preferences > Ask before Rasterize, Merge Down and Flatten Image brings it back.

Every color is edited in one compact field: a swatch and its hex code on one row. Click the swatch to open its popup, which holds:

  • a picker, with an alpha bar where the color has one;
  • a hex box, which takes #RGB, #RRGGBB, or #RRGGBBAA when you press Enter or click away;
  • Pick: click the canvas and the field takes the color shown there. Esc cancels;
  • the recently chosen colors and the swatch palette, the same in every field. Click either to set the color; + adds the current color to the swatches, - removes it, and a swatch can be dragged to reorder it. Both are kept between runs.

Fields for text, fills, shapes, gradient stops, effects, photo filter, text styles, and New Document all work this way. A hex code, a canvas pick, or a swatch is one undo step each.

Gradient presets

Every gradient editor has a preset strip above its bar: gradient fills, the gradient map, the gradient overlay effect, and the gradients on texture graph nodes. The list on the left picks a set, and clicking a swatch puts that gradient in the bar as one undo step. The swatch matching the gradient you’re editing is outlined.

The built-in sets are Grays, Spectrum, Metals, Sunsets, Catppuccin Mocha, Catppuccin Latte, and Duotones. My Presets holds your own:

  • + saves the gradient being edited under a name. Saving under a name already used replaces that preset;
  • drag a saved preset to reorder it, or right-click it to Rename or Delete it;
  • the folder button imports a GIMP gradient (.ggr) into My Presets, and the disk button exports the gradient being edited as one. Right-click any preset, built-in or yours, to export that one instead.

Your presets are kept between runs and offered by every editor, so a gradient saved from a fill is there on a gradient map too.

GIMP blends a gradient’s colors as they’re stored, in sRGB, while ImageGui blends in linear light, so an imported gradient gets the extra stops it needs to look the way it did in GIMP, and an exported one is cut into enough segments to look the same there. Hard edges come through both ways. GIMP’s foreground and background colors have no equivalent, so they import as black and white.

Pattern fills

A fill layer whose Type is Pattern repeats an image across itself. Each document keeps its own patterns, saved inside the project, and the inspector’s Pattern list picks one. Load pattern… adds an image file and fills with it, and Edit > Define Pattern adds what the canvas shows: the selection’s contents, with anything outside a feathered or shaped selection left transparent, or the whole canvas with no selection. Layer > New > Fill Layer > Pattern fills with the newest one, and the Pattern overlay effect tiles the same patterns over any layer.

A tile is laid at its own pixel size, starting from the layer’s top-left corner. Scale sizes it, Angle turns it, and Offset shifts it in canvas pixels. Moving the layer moves the pattern with it, while resizing the layer only shows more or less of it.

Texture graph fills

A fill layer whose Type is Texture graph draws a procedural texture: a network of noise, pattern, adjustment, and filter nodes, rendered into one square tile that repeats without a seam. Layer > New > Fill Layer > Texture Graph adds one covering the canvas, starting as soft clouds.

  • Seed is mixed into every node’s own seed, so a new seed draws a different texture of the same kind. Re-roll picks one at random.
  • Mapping is Tile, which repeats the tile across the layer, or Stretch, which lays one tile over the whole layer so it scales and turns with it.
  • Under Tile, Tile size is how wide one tile is on the canvas, and Scale, Angle, and Offset work as they do for a pattern.
  • Resolution is the size the tile is rendered at. Automatic follows how large the tile is drawn, up to 4096 pixels, so the canvas stays quick when zoomed out and an export gets full detail. A fixed size keeps the same detail at every zoom, up to 8192 pixels.

The texture is rendered once and shared by every part of an export, and it’s saved inside the project. SVG export embeds it as an image.

The texture graph editor

Edit graph… in the Fill panel, Edit Texture Graph… in a layer’s right-click menu, or Layer > Edit Texture Graph… opens the layer’s graph in a window of its own, titled Texture Graph: and the layer’s name. A new texture graph fill opens it straight away. Each layer gets its own window, so two graphs can be open side by side.

The canvas shows the graph’s nodes with their links running left to right into Output, and each node shows a small preview of what it draws. Drag the background with the middle mouse button to pan, and scroll to zoom.

  • Add a node from Add node on the toolbar, a right-click on empty canvas, or Space. Type to search, then click a node or press Enter for the first match. Drag a link from a pin into empty space and the menu lists only the nodes that can take it, and links the one you pick.
  • Link two nodes by dragging from an output pin to an input pin. An input takes one link, so delete the old one first. A link that would make the graph loop back on itself, or join two inputs, is refused, and a tooltip says why.
  • Select a node to edit its settings in the inspector beside the canvas: sliders, colors, gradients, choices, and seeds, each with Re-roll for a new one. Dragging a slider is one undo step however long you drag.
  • Delete removes the selected nodes and links, and Ctrl+D duplicates the selected nodes. A graph always keeps one output node, so its last one can’t be deleted.
  • Tidy spreads the nodes out so links run left to right and nothing overlaps. Fit centers the graph and zooms so all of it shows.

The same editor opens on a graph mask or a graph selection; see Graph masks and selections.

Every change, moving a node included, is one step in the document’s history, so Ctrl+Z in the editor undoes the same steps it does anywhere else. A layer whose pixels are locked opens read-only: you can look around and select, and any change is refused with the lock’s reason.

Nodes for materials

Four nodes are made for building materials such as weathered stone, rust, and paint:

  • Distance (Filter) draws how far each pixel is from the nearest pixel at or above Threshold, as a fraction of the tile, reaching white at Max distance. It’s exact and wraps across the tile’s edges, so a soft edge or a halo around shapes stays seamless.
  • Slope Blur (Filter) runs its input down the slopes of a second, grayscale input, in Samples steps covering Intensity of the tile. Flat parts of the slope don’t move, and a negative intensity runs it uphill instead.
  • Curves (Adjust) bends values through a tone curve. Click the curve in the inspector to add a point, drag a point to move it, or drag it off the box to remove it. The curve never folds back on itself, so brighter in stays brighter out.
  • Histogram Scan (Adjust) sweeps a threshold across its input: Position 0 is all black and 1 is all white, and Contrast narrows the ramp between until, at 1, it’s a hard edge. It’s the quickest way to choose how much of a noise covers the surface.

Flood Fill (Filter) gives every separate shape in its input a value of its own, which is how a wall of bricks or a floor of tiles gets a different shade in each one. A shape is the pixels at or above Threshold that touch, along an edge when Connectivity is 4-connected, or at a corner too when it’s 8-connected. A shape that runs off one side of the tile and on at the other counts as one, so the texture still repeats without a seam. Output chooses what each shape gets: a Random gray, a Random color, a Gradient across it at a random angle, or its Index, counting the shapes from the top left. Seed re-rolls the grays, colors, and angles, and a shape keeps its own when another is added or removed. Everything outside the shapes is black.

Two more nodes turn a height map into the maps a 3D renderer lights a surface with:

  • Height to Normal (Filter) turns a grayscale height into a normal map, with white the highest. Strength is how high white stands above black, as a fraction of the tile’s width, so the same graph gives the same bumps at every resolution. Format is OpenGL (Y+), which Blender reads, or DirectX (Y-), which flips green for engines that read it the other way. It wraps across the tile’s edges, so a seamless height gives a seamless normal map.
  • Curvature from Normal (Filter) reads a normal map and draws mid gray where the surface is flat, lighter on ridges and edges, and darker in hollows, which is a good start for wear on edges and dirt in crevices. Set Format to match the normal map.

Three more work on a normal map once it’s made. None of them asks which way green runs: they give the right answer for OpenGL and DirectX maps alike, as long as both inputs of Normal Blend use the same one.

  • Normal Blend (Filter) lays a Detail normal map over a Base one by Reoriented Normal Mapping, the blend game engines use for detail normals. The detail follows the base’s slopes instead of flattening them, so fine grain stays visible on the sides of a bevel. Amount fades the detail from none to all of it. With nothing linked to one input, it’s read as a flat surface.
  • Normal Strength (Filter) makes the bumps steeper or flatter. It multiplies each normal’s tilt by Strength and brings it back to full length, so 0 flattens a map and 1 leaves it as it is.
  • Normalize (Filter) brings every normal back to full length. A blur, a resize, or a blend between two normal maps leaves them shorter than they should be, which a renderer lights as too dark.

Presets and settings in the Fill panel

Load preset…, in the Fill panel or on the graph editor’s toolbar, replaces the layer’s graph with a ready-made texture: Stone, Wood, Brick, Clouds, Paper, or Rust. The seed, mapping, tile size, and placement stay as they were. One undo brings the old graph back.

A graph can show some of its settings in the Fill panel, under Texture, so a texture can be tuned without opening its graph. Each preset shows the few worth changing: a stone’s size and crack width, a wall’s rows and mortar, how much of a sky is clear. They use the same controls the editor’s inspector does, and dragging one is one undo step.

  • Show a setting by right-clicking it in the editor’s inspector and choosing Show in Fill Panel. The same menu hides it again, and gives it a Label of its own, so “Input black” can read “Clear sky.” Settings are listed in the order you show them.
  • Save as preset… keeps the graph, with the settings it shows, under a name. Your presets are listed under Your presets in Load preset…, and a right-click deletes one. Saving under a name you already use replaces that preset.

Deleting a node takes its settings out of the Fill panel with it.

Materials: a graph with several outputs

A graph can have more than one Output node, each one map of a material: Base color, Roughness, Metallic, Normal, Height, Ambient occlusion, or Custom for a map of your own. Add one from Add node like any other node, and set its Map and Name in the inspector. The Stone, Wood, Brick, Rust, Marble, Granite, and Bark presets come with roughness, normal, height, and ambient occlusion maps, and rust with a metallic one too.

A fill layer, a graph filter, or a mask shows one output at a time. When a graph has several, the Fill panel and the inspector show an Output menu to choose which, starting with the first, and choosing is one undo step. To write every map to files, see Exporting a material.

Graph filters

A texture graph can filter pixels that are already in the document, as well as draw its own. Layer > New > Graph Filter Layer adds an empty group, above the selection, holding a Graph Filter, and opens its graph in a window titled Graph Filter: and the layer’s name. The group passes through, so the filter acts on everything beneath it, the way an adjustment layer does. Graph Filter is also in the inspector’s Add adjustment list, to filter one layer or group.

A new filter’s graph is an Image node linked to the output, which changes nothing. The Image node reads the pixels entering the filter, and whatever reaches the output replaces them. In a filter’s editor the Add node menu lists the Input category, which a fill, mask, or overlay has no use for.

  • Image nodes are the Image node and every node it feeds. They carry a colored band across the top and work at the image’s own pixels, so a blur or an emboss there is as sharp as the photo. Their previews are drawn over a small copy of what is beneath, and are approximate: the canvas is the real preview.
  • Lengths, such as a blur’s radius, are a fraction of the layer’s height, so a filter looks the same at the preview’s size and at the export’s.
  • Tile nodes, the rest, render as one seamless tile, as in a fill, and the filter lays that tile over the image where an image node reads it. Mapping, Tile size, Scale, Angle, and Offset in the inspector place it, and Seed with Re-roll gives every noise in it a new seed.
  • A link from an image node into a node that only makes tiles, such as Transform or a generator, is refused, and a tooltip says why.
  • Layer nodes read another layer of the document, drawn through its own adjustments and at its place on the canvas, so one layer can mask or tint what is beneath another. Pick the layer in the node’s settings. The list grays out the filter’s own layer, the groups holding it, and any layer that already depends on it, since reading one of those would go round in a circle. A hidden layer can still be read. If the layer is deleted the node reads nothing and says so, until the delete is undone or another layer is picked. A saved preset forgets which layer its Layer nodes read.

The filter’s section in the inspector shows a thumbnail of its output, and Edit graph… opens its graph again. Every edit is one step in the document’s history, and a layer whose pixels are locked opens its filter read-only. Like every adjustment it can be faded, blended, limited to a mask, and switched off.

A row’s right-click menu also tags layers with a color Label.

Placing a project

File > Place… takes an .imagegui project as well as an image. An image becomes an image layer at its own pixel size. A project asks whether to Embed a copy of it in this project or Link to its file, and becomes a layer of its own at its canvas’s size. That layer is drawn by evaluating the whole placed project at the size it appears on the canvas, so its text and shapes stay sharp however far it is scaled, and like any layer it takes adjustments, effects, masks, blend modes, locks, and the Move tool’s transforms.

An embedded project is saved inside this one and never changes on its own. A linked project follows its file: when the file is saved again, by ImageGui or anything else, the layer takes in the new version as one undo step. A linked project whose file has moved opens with its edits and its shape kept, drawing nothing, and Layer > Relink Project… points it at the file wherever it is now. Save Packaged Copy carries linked projects’ files along, as it does images.

Layer > Edit Contents… opens the selected placed project as the current document. This project is saved first, and saving the placed project brings you back to it with the change in place: a linked project is simply read again, and an embedded one takes in the edit as an undo step, leaving this project to save. File > Return to … goes back without saving, and saving the placed project under another name keeps it as a project of its own.

Replacing a layer’s contents

Layer > Replace Contents…, also on a layer’s right-click menu in the Layers panel, puts another file in place of an image layer’s image or a placed project’s. Everything else about the layer stays: its name, placement, perspective and mesh warp, adjustments, masks, effects, locks, and links. It’s one undo step, and saved versions and git diffs list it as a change of the layer’s original.

A file the same size as the old contents takes their place exactly. When it’s a different size, ImageGui asks whether to Fit it inside the old contents’ bounds, keeping its own shape and centered, or Keep its size, so it’s drawn at the same scale the old contents were, centered where they sat. A layer whose position is locked, or which has a mesh warp, always fits.

An image layer takes an image file. One made by rasterizing or merging, whose pixels live in the project, becomes a layer linked to the file you chose, and undo brings its own pixels back. A placed project takes another .imagegui project and stays embedded or linked, as it was. A layer whose pixels are locked can’t have its contents replaced.

Converting layers to an embedded document

Layer > Convert to Embedded Document turns the selected layers into one embedded project, the same kind of layer an embedded File > Place makes. The layers must share a group. Their copies go into a project of their own whose canvas is just big enough to hold what they draw, in the canvas’s own pixels, and the new layer is placed where they were, so the image doesn’t move. It sits where the top selected layer was and takes that layer’s name. Images inside are packaged with it, so it never needs their files. Layer > Edit Contents… opens it to change the layers themselves.

What travels with the layers: their locks; a link between two of them, which goes inside; a link to a layer left outside, which links the new layer instead; and clipping, when every selected layer was clipped to the same layer below, which the new layer then clips to. A mask elsewhere that selects from one of the layers’ transparency is baked into pixels first, as deleting the layer would bake it, and text following a path on the other side of the boundary keeps the path where it is.

Layer > Expand Embedded Document puts the layers back where they were. If the embedded layer carries nothing of its own beyond where it’s placed, its layers come out loose; otherwise they come out in a group that keeps its adjustments, effects, blending, opacity and transform, so the image stays the same. A locked embedded layer has to be unlocked first. Converting and expanding are one undo step each.

Finding a layer

Once a document has four or more layers and groups, the search box over the rows shows only the layers whose names contain what you type, and the Filter button beside it narrows them by kind (image, text, shape, fill, or group), color label, visibility, or lock. A match inside a group shows with the groups around it, even folded ones, and nothing about the document changes: clear the box and the panel is as it was. Rows can’t be dragged to reorder while a filter is on.

With the Move tool, Ctrl-click the canvas (or Alt-right-click it) to select the topmost layer drawn there, or right-click to list every layer drawn there and choose one. Hidden layers, the transparent parts of a layer, and what its masks hide don’t count, and picking a layer inside a folded group unfolds the group so its row shows.

Using the panels from the keyboard

Ctrl+F6 moves the keyboard from the canvas to Layers, then to each other open panel in the order their tabs sit, and back to the canvas; Ctrl+Shift+F6 goes the other way. A panel behind another tab comes forward when it is reached, and whatever has the keyboard is outlined in the theme’s focus color. Clicking the canvas, or anywhere outside the panel, gives the keyboard back to the canvas.

While Layers has the keyboard, the up and down arrows select the row above or below, and with Shift they add the next row to the selection or take it back out. Space hides the selected layers, or shows them if the selected one is hidden, in one undo step. F2 renames the selected layer, and Alt+Up and Alt+Down move it up or down the stack. The arrows go back to nudging the selected layer once the canvas has the keyboard again; clicking a row with the mouse doesn’t change what they do.

Locking layers

The padlock at the right end of a layer’s row locks it, and its menu opens beside the panel; on an unlocked layer it appears faintly when the pointer is over the row. Position stops it being moved, scaled, nudged, aligned, or straightened; Pixels stops adjustments, effects, masks, and text edits; All also locks its blend mode, opacity, and clipping. A group’s lock covers everything inside it. Whatever a lock refuses is grayed out, and its tooltip says which lock is in the way. Each change of lock is one undo step.

Blending and opacity

The Blend picker offers twenty-seven modes, and the opacity slider fades a layer. The last, Normal Detail, is only for normal maps; see Working on a normal map. A group normally blends its own layers together first; choose Pass Through at the top of its blend list to let each layer blend straight onto what is below the group.

Blend If

Layer > Blending Options… shows a layer only where colors fall within a range. Pick a channel (Gray, Red, Green, or Blue), then drag the handles under the two gradient bars:

  • This Layer hides the layer’s own pixels outside its range, such as a sky’s darkest blue.
  • Underlying Layer lets the pixels beneath show through wherever they fall outside their range.

Hold Alt as you drag a handle to split it in two, so the layer fades in across the gap rather than cutting off. Every change shows on the canvas as you make it, one undo takes the whole visit back, and Reset returns both ranges to the full range. A pass-through group has no composite of its own, so it can’t use Blend If until its mode is changed. Blend If is saved in the project and exports exactly as the canvas shows it.

Moving and scaling

With the Move tool (V), drag inside a selected layer’s outline to move it, a corner to scale it in proportion (Shift scales freely), or an edge to stretch it. The arrow keys nudge it a pixel at a time, or ten with Shift. Dragged layers snap to the canvas, other layers, and guides; hold Ctrl to drag freely.

Ctrl-drag an edge to skew the layer along it. Ctrl+Shift-drag a corner to move that corner alone and give the layer a perspective; once distorted, its corners move one at a time with a plain drag. Any layer can be distorted: text, fill, and shape layers are drawn in their own frame and then warped, so text stays editable and sharp, and a group’s perspective carries everything in it.

While you move, resize, skew, or distort a layer, or resize a text box, smart guides show what it lines up with and how far it is from its neighbors. A line runs along every edge or center it shares with another layer or an artboard, and the gap to the nearest layer on each side is labeled in pixels; inside an artboard, the gaps run to its edges. When a layer sits evenly between two others it snaps there, and both gaps show the same value. Resizing snaps too: the edge you drag catches on lines and on even spacing, while the layer is upright. Smart guides follow View > Snap, and holding Ctrl hides them along with the snapping, except during a skew or a distort, where Ctrl is part of the drag.

Warping

Edit > Transform > Warp lays a grid over the selected layer, in place of its transform box. Drag a point to pull the layer with it, or one of its handles to bend the lines either side of it, and the layer follows the grid as if it were printed on a sheet of rubber. The grid starts at three cells by three; the same menu offers four, five, or six, and changing the grid keeps the bend as nearly as the new grid can hold it. Press Enter or Escape, choose Warp again, or select another layer to put the box back; the bend stays. Remove Warp straightens the layer again.

Any layer can be warped. Images and placed projects are resampled through the grid with the document’s resampling filter; text, shapes, and fills bend their outlines, so they stay sharp at every size; a group bends everything in it. The warp is applied in the layer’s own frame, before its perspective and placement, so moving, scaling, or distorting a warped layer carries the bend with it. Each drag is one undo step. A position-locked layer can’t be warped, and a layer inside a warped group is warped with its group. Text is typed straight while it is edited on the canvas, and a warped shape can’t have its points edited or be combined until the warp is removed. A layer’s masks and limits bend with it, so a mask stays on the part of the image it was made for, and a selection turned into a mask or limit while the layer is warped lands where it was drawn. A vector mask can’t be drawn on a warped layer, but one it already has bends with it.

Linking layers

Select two or more layers and choose Layer > Arrange > Link Layers to have them move together without grouping them. Moving, scaling, skewing, distorting, nudging, or aligning any one of them moves the others by the same change on the canvas, wherever they sit in the layer tree. A chain icon at the right of each linked row shows which layers are linked; click it to select them all. Linking a layer to one that is already linked adds it to that link.

Layer > Arrange > Unlink Layers takes the selected layers out of their link, and the rest stay linked, as they do when one of them is deleted. A linked layer whose position is locked keeps all of them in place, and the tooltip names it. Each link change is one undo step, and links are saved with the project.

Effects

Add effect in the inspector’s Effects section adds a drop shadow, a stroke, an outer glow, an inner shadow, an inner glow, a color overlay, a gradient overlay, a pattern overlay, a bevel and emboss, and a satin to any layer, each with its own blend mode. They follow the layer’s shape, so they work on text and groups too. Each effect a layer has gets a card with its switch, which keeps the effect’s settings while it’s off, and a button that removes it; Add effect lists only the ones the layer doesn’t have yet.

A stroke’s Position puts it outside the edge, inside it, or centered on it. The Color overlay paints the layer one color, and the Gradient overlay paints it with a gradient edited like a gradient fill’s, linear along an angle or radial, fitted to the layer’s pixels; Scale stretches it. The Pattern overlay tiles one of the document’s patterns over the layer from the corner of its pixels, so it moves with the layer, at a Scale and Angle of its own. Set its Source to Texture graph and it draws a texture graph instead, with the same seed, mapping, tile size, and placement settings a texture fill has, and Edit graph… opens the graph in the editor. A document with no patterns starts the overlay as a texture graph. A preset leaves the overlay behind, since what it draws belongs to the document. The Inner glow lights the layer from its edge inward, or from its middle out. Overlays and inner glows lie inside the layer’s edge, over anything clipped to it.

Shadows follow the document’s light: Layer > Effects > Global Light turns every shadow with Use global light ticked at once, in one undo step, and so does changing the angle of any one of them. Untick it to give a shadow an angle of its own. Effects pasted or applied from a preset take the document’s light too.

Bevel and emboss shades the layer’s edge as a slope lit from one side, so it looks carved. Its Style puts the slope inside the edge (Inner), outside it so the canvas rises to meet the layer (Outer), across it so the layer looks pressed up out of the canvas (Emboss), or down into the edge from both sides like a stamp (Pillow). Depth steepens the slope, Size widens it, Soften blurs the shading, and Direction raises or sinks it. The light has an Angle, which follows the global light like a shadow’s, and an Altitude above the canvas. The Highlight and Shadow each have their own color, opacity, and blend mode.

Satin lays a silky sheen inside the layer: its own shape, softened by Size, moved by Distance both ways along an Angle, and laid where the two copies differ, or where they agree with Invert ticked, which is how it starts.

Layer > Effects > Copy copies the selected layer’s effects, and Paste gives them to every selected layer in place of their own, as one undo step. Both are on a layer row’s right-click menu too. They are separate from copying adjustments, so each keeps what it holds. Pasted effects keep their size on the canvas: a 3 px stroke is 3 px on a small layer and a big one alike. The layer thumbnails show each layer with its effects.

Layer comps

View > Layer Comps keeps named layouts of the layers, so one project can hold several versions of a design. New saves which layers are shown, where each sits, its opacity, blend mode, and which of its effects are on; Apply (or a double click) goes back to the chosen comp in one undo step; Update replaces what it remembers with the layers as they are now; and the name field beside Rename and Delete manages the list. Layers deleted since a comp was saved are skipped, layers added since keep what they have, and a locked layer keeps what its locks protect. Pixels, adjustments, and text are the same in every comp. Export Animation can play the comps as the frames of a GIF or WebP.

Artboards

An artboard is a named rectangle of the canvas that exports as an image of its own, so one project can hold every size of a social post or every icon of a set. Layer > New > Artboard asks for a name, a size (type one, or pick a common social or icon size), and a background: white, black, a color, or transparent. The first artboard takes the canvas, so the image becomes the first of the set; each later one goes to the right of the last, and the canvas grows to hold it.

Whatever sits on an artboard belongs to it: a layer at the top of the stack belongs to the artboard its middle is in. Each artboard’s background is a fill layer at the bottom of the stack, named after it, so it can be recolored or given a gradient in the Fill panel like any other fill. With the Move tool, drag an artboard’s name to move it and everything on it, or click the name to choose it and drag an edge or corner to resize it, which leaves what is on it where it is. Escape, or a click elsewhere on the canvas, goes back to the layers. Layer > Artboards… lists them all, with their names, places and sizes in pixels and their background colors, each editable, and deletes them. Deleting an artboard deletes its background and leaves everything else on the canvas.

When a document has artboards, Export offers Each artboard, which writes every artboard beside the file you chose, named after it and the artboard (post-Story.png), rendered over its own rectangle alone. Export Layers offers Each artboard too, and a batch can write each artboard of every project in it. A document with no artboards exports exactly as before.

Text

Layer > New > Text Layer (Ctrl+Shift+T) adds a line of text. The inspector’s Text section sets what it says, the font, size, alignment, line spacing, and color. Text stays sharp at any size, because it is drawn from the font’s outlines.

To type on the canvas, double-click a text layer, or choose the Text tool (T) and click it. Clicking where there is no text adds a new text layer. While editing, the arrows, Home, End, Ctrl+A, and the clipboard work as in any editor, a double click selects a word, a triple click a line, and dragging a selection moves it (Ctrl copies). Ctrl+Enter or a click elsewhere finishes; Escape puts the text back.

Wrap in a box turns a caption into a paragraph that wraps to a box you can resize.

A character the font has no glyph for, such as an emoji, a Chinese, Japanese, or Korean character, or a symbol, is drawn in the first installed font that has it instead of as an empty box: first the fonts the project carries, then the emoji, symbol, and CJK fonts each platform installs (Segoe UI Emoji and Symbol, Apple Symbols, the Noto families, DejaVu Sans, and others). The caret and wrapping measure it in that font, and Save as Package carries the fallback font along with the text’s own. Color emoji fonts that hold only images are skipped, because text is drawn from outlines.

Select some of the text while editing it and a bar floats over it. Its first row sets the selection’s bold and italic faces (Ctrl+B, Ctrl+I), size, color, and font. Its second row underlines it (Ctrl+U) or strikes it through, at the position and thickness the font gives; makes it superscript or subscript; loosens or tightens its tracking; and raises or lowers it off the baseline. Its third row aligns the paragraphs the selection touches left, center, right, or justified, each paragraph on its own. Justify spreads every line of a boxed paragraph but its last across the box; the inspector’s Alignment sets every paragraph at once.

Leading and paragraphs, folded away under the inspector’s Text section, sets how far apart lines and paragraphs sit, all in ems of the text’s size:

  • Auto leading spaces lines by the line spacing times their largest size. Clear it to set the Leading, baseline to baseline, yourself. Leading belongs to characters, as size does, so a line takes the largest leading on it.
  • Before and After add space above and below a paragraph. The space before the first paragraph is left out, so the text still starts at the top of its box.
  • First line, Left, and Right indent a paragraph from the box’s edges. Below zero, the first line hangs out to the left of the rest, as far as the box’s edge.

While you edit the text on the canvas, these apply to the paragraphs your selection touches, or the caret’s paragraph, and leading to the selected characters or the caret’s paragraph; they drag rather than take typing, and using them doesn’t end the edit. Otherwise they apply to all of the text. Point text has no edges to indent from, so it takes leading only.

OpenType features, folded away below it, turns on the extras a font draws: Ligatures (on unless you turn them off) and Discretionary ligatures, Small caps, old-style or lining Figures, Tabular figures for columns of numbers, Fractions, Stylistic sets 1 to 20, and Kerning (on unless you turn it off). Only the features the text’s font has are listed. While you edit text on the canvas they apply to the selection, or the caret’s paragraph, without ending the edit; otherwise to all of the text, each switch one undo step. The caret still stops between the letters a ligature joins.

Vertical sets the text top to bottom, in columns that run from right to left, as Chinese, Japanese, and Korean are often set. Their characters stand upright; Latin letters and digits lie on their side, as HarfBuzz’s vertical shaping sets them. Once the text is vertical, Upright appears below the Path list and stands the selected characters (or, with nothing being edited, all of the text) upright too, which is how a sign spells a word down a column. Alignment runs down the columns: left sets them from the top, right to the bottom. Boxed vertical text wraps at the box’s height and adds columns to the left; columns that don’t fit the box’s width aren’t drawn. While you edit vertical text the caret lies across the column, Up and Down move along it, and Left and Right move to the next or previous column. Vertical text can’t follow a path.

When the text’s font is a variable font, Font axes, folded away above the OpenType features, has a slider for each of the font’s axes, such as weight, width, slant, and optical size, and Font’s default puts them all back. Like the features, the sliders apply to the selection while you edit on the canvas, otherwise to all of the text, and each drag is one undo step. A font that isn’t variable shows no axes.

Text styles

View > Text Styles keeps named styles in the document, so a heading or a caption looks the same wherever it is used:

  • A character style holds a font, size, color, tracking, baseline shift, underline, strikethrough, OpenType features, Upright, and a variable font’s axes. It applies to characters.
  • A paragraph style holds alignment, space before and after, and indents. It applies to whole paragraphs.

New makes a style from the selected text and links the text to it. Clicking a style applies it: to the selected text layers, or, while you edit text on the canvas, to the selection (a character style) or the paragraphs it touches (a paragraph style). Using the panel doesn’t end the edit.

Choose a style to edit it below the list. A change, or Redefine, which takes the selected text’s values into the style, updates every text linked to it, in one undo step. Text you changed by hand keeps that change: if a linked word is struck through and the style isn’t, it stays struck through when the style changes. A + beside a style’s name means the selected text is linked to it but differs from it; clicking the style again clears the differences. Delete removes a style and leaves its text looking as it did.

Styles are saved in the project. Text copied on the canvas and pasted into another document brings the styles it uses, joining a style of the same name there if it has one; undoing the paste removes them again.

Layer > Warp Text, or Warp in the inspector’s Text section, bends a text layer into an arc, arch, bulge, flag, wave, fish, rise, or squeeze. Each starts at a bend of 50%; the inspector’s Bend, Horizontal, and Vertical distortion sliders (-100% to 100%) adjust it, and None straightens it again. The warp bends the text’s outline rather than its pixels, so the text stays editable and sharp at any size, and moving, scaling, and distorting the layer work on the warped text. While you edit warped text on the canvas it is shown straight, so the caret sits on the letters; it bends again when you finish. A warped paragraph’s handles scale it rather than resize its box.

Finding and replacing text

Edit > Find and Replace (Ctrl+H) searches the text of every text layer in the image, including text in groups, boxed text, text on a path, and every styled run. Type what to find, and choose Match case to tell capitals apart, Whole words to skip matches inside longer words, or Regular expression to search with a .NET regular expression, where ^ and $ match at the start and end of each line and $1 in the replacement stands for the first group. The window says how many matches there are and in how many layers. If you have text selected on the canvas when you open it, that text is filled in.

Next and Previous go through the matches from the top layer down, the way the Layers panel lists them, and wrap round at the end. Each opens its layer for editing on the canvas with the match selected, so you can see it in place and type over it. Replace replaces the selected match and goes to the next; with no match selected, it finds one first. The replacement takes the style of the first character it replaces, so replacing a bold word gives a bold word, and the rest of the text keeps its styles. Each Replace is one step to undo.

Replace all replaces every match in every text layer as one step to undo. A layer whose pixels are locked, or whose fonts aren’t installed, is left as it is, and the window names it.

Checking spelling

While you edit text on the canvas, words the dictionary doesn’t know are underlined with a wavy red line. The check runs in the background as you type, so it never slows typing down. Right-click an underlined word for suggestions: choosing one types it over the word, so Ctrl+Z inside the edit takes it back. Add to Dictionary counts the word as spelled right from then on, in every image, and Ignore passes over it until ImageGui closes. Words with digits in them, words in capitals, and web and email addresses aren’t checked.

Edit > Check Spelling (F7) steps through the misspelled words in every text layer, from the top layer down, starting where your caret is and going round to where it began. Each word opens on the canvas, selected, and the window offers suggestions. Change replaces the word with the one chosen or typed in Change to, as typing over it would, and goes on; Ignore once leaves it and goes on, Ignore all passes over it everywhere, and Add to dictionary adds it. Nothing changes until you press a button. A layer whose pixels are locked, or whose fonts aren’t installed, is passed over, and the window says so at the end.

ImageGui comes with English (US) and English (UK) dictionaries. Preferences > General sets the language and turns the underlines off, and lists the words you’ve added so you can remove one. The inspector’s Spelling combo gives one text layer its own language, or tells ImageGui not to check it. That choice stays with ImageGui rather than in the image, so the same file opened on another computer follows that computer’s Preferences.

Text on a path

Text can follow a path instead of a straight line. With the Text tool, click a path drawn with the Path tool, or a line, ellipse, or rectangle, and type: the text starts where you clicked. To put existing text on a path, select it and choose Layer > Attach Text to Path, or pick the path from Path in the inspector’s Text section. Each letter stands upright on the path, turned to its direction, and an underline or strikethrough bends along it. An ellipse’s path runs from its left over the top, so text on a circle reads upright across its top.

The text’s Alignment says whether the line starts, centers, or ends at its place on the path, and Position moves that place along the path (0% is the path’s start, 100% its end). Flip runs the text the other way, on the path’s other side. Text longer than an open path carries straight on past its end; round a closed one it wraps.

The text follows its path layer: edit the path’s points, or move, scale, or rotate the layer, and the text goes with it. While you edit text on a path on the canvas, the caret and selection travel along the path. Text on a path can’t be warped or wrapped in a box; Layer > Detach Text from Path, or None in the Path list, sets it straight again. If you delete the path layer, the text keeps the path where it last was, in the same step, so undoing the delete puts both back.

Text inside a shape

Text can fill a shape instead of a box. With the Text tool, click inside a closed shape, such as an ellipse, a rectangle, a star, or a closed path drawn with the Path tool, and type: the text is added above the shape and its lines wrap inside the outline. Clicking on the outline itself still puts text on the path, and holding Alt while you click makes ordinary text wherever you click. To flow existing text into a shape, select it and choose Layer > Flow Text into Shape, or pick the shape from Inside shape in the inspector’s Text section.

Each line is as wide as the shape is across that line’s whole height, so no letter pokes out where the outline curves in, and a line steps down until there is room for its first word. Where a path crosses itself and splits a line in two, the line takes the wider side. Inset keeps the text that far from the outline on every side. Alignment, line spacing, paragraph spacing, styles, mixed runs, and OpenType features all work as they do in a box. Text that doesn’t fit stops at the bottom of the shape.

The text follows its shape: change the shape, or move, scale, or rotate its layer, and the lines reflow. Text inside a shape can’t be warped, set vertically, wrapped in a box, or put on a path, and those controls say so. Layer > Release Text from Shape, or None in the Inside shape list, turns it back into text wrapped in a box the size of the shape. If you delete the shape’s layer, the text keeps the outline where it last was, in the same step, so undoing the delete puts both back.

Shapes

The Shape tool (U) draws a rectangle, rounded rectangle, ellipse, line, polygon, star, or custom shape as a layer of its own. Press U again to move to the next shape, or pick one from the strip beside the tools, which also sets the fill, the stroke, the corner radius, the polygon’s number of sides, and the star’s points and inner radius for the next shape you draw. Hold Shift to draw a square or a circle, or to keep a line to 45 degrees; hold Alt to draw out from the center. Layer > New > Shape adds one in the middle of the image instead.

A shape is drawn from its outline, so it stays sharp however far you scale it. The inspector’s Shape section changes its fill (a color or none) and stroke (a color and a width, or none) afterward, and the Move tool’s box moves, scales, rotates, and skews it like any other layer. Shapes take adjustments, masks, blend modes, opacity, clipping, effects, and locks too. Select > From Shape turns the selected shape’s outline into a selection.

Dashes, caps, and joins

Once a shape is stroked, the inspector’s Shape section also styles the stroke. Dashes breaks it up: the presets (Dashed, Long dashes, Dotted, Dash dot) are worked out from the stroke’s width when you pick one, and Custom takes your own lengths in pixels, drawn and gap in turn, such as 12 4 0 4. A length of 0 is a dot, which only shows with round or square caps, so picking Dotted turns butt caps round. Caps finishes the ends of a line, an open path, and every dash: butt stops at the end, square reaches half the width past it, and round finishes it with a half circle. Joins turns the outside of each corner: miter carries the edges on to a point, round rounds it, and bevel cuts it off. A miter longer than the Miter limit, measured in half the stroke’s width, is beveled instead; 1 bevels every corner and 4 is the usual default. Dash lengths belong to the shape, so they grow and shrink with it when the Move tool scales it.

Arrowheads, stars, and corners

A line or an open path can end in an arrowhead. In the inspector’s Shape section, Start arrow and End arrow each pick a filled triangle, an open chevron (drawn with the stroke’s own caps and joins), a circle centered on the end, or a bar across it. W sets how wide it is across the stroke and L how far it reaches back along it, both in widths of the stroke, so an arrowhead grows when you make the stroke wider. An arrowhead replaces that end’s cap, points the way the line arrives, and is drawn whole however the dashes fall.

A star has a number of Points and an Inner radius: how far out its inner corners lie, as a share of the way to its points. At 100% it is a polygon of twice as many sides; lower values sharpen the points.

A rounded rectangle’s corners start linked, with one Corner radius for all four. Untick Link corners to give each its own, top left, top right, bottom right, and bottom left; ticking it again gives every corner the top left’s. Two corners on the same side share it in proportion to their radii, so a large corner beside a square one can use the whole side.

Drawing paths

The Path tool (P, the pen in other editors) draws your own shapes out of curves. Click to put down a corner; press and drag to put down a smooth point, whose handles follow the pointer and bend the curve through it. Hold Shift to put the next point at a multiple of 45 degrees from the last. Click the first point to close the path, or press Enter to finish it open; Backspace takes the last point back and Escape abandons the path. A finished path becomes a shape layer painted with the fill and stroke in the strip beside the tools, and an open one is always stroked. Set the strip’s first list to Selection and the path becomes the selection instead, added to, subtracted from, or intersected with the one you have by holding Shift, Alt, or both as you put down its first point.

The Direct Selection tool (A) shows the selected path layer’s points and handles. Drag a point to move it with its handles, or drag a handle to reshape the curve: a smooth point turns its other handle to match, and holding Alt moves one handle alone. Alt-click a point to make it a sharp corner. Each drag is one step to undo. The inspector’s Closed box opens or closes the path, and Select > From Shape selects inside it like any other shape.

Combining shapes

One shape layer can be made of several shapes. With a shape layer selected, draw another shape over it holding Shift to add it, Alt to cut it out, or both to keep only where the two overlap. The second list in the strip beside the tools does the same without the keys, and also offers Exclude, which keeps where exactly one of them covers and leaves the overlap a hole; with it set to New layer a shape is a layer of its own, as usual. The Path tool uses the same list and keys for the path it draws. Layer > Combine > Combine Shapes merges the selected shape layers into one, keeping the fill and stroke of the lowest. Each step is one to undo.

The fill and stroke paint the outline the shapes make together, so a hole is outlined too and an edge inside the shape is not. The inspector lists the shapes it is made of, where you can change how each combines or remove it, and its Fill rule decides what happens where a path crosses itself or loops inside itself: Non-zero fills it and Even-odd leaves it a hole. Select > From Shape selects the combined outline, holes and all.

Custom shapes

The Shape tool’s last outline, Custom, draws a shape from your custom shape library. Click the thumbnail beside the outline list to pick one. The library starts with arrows, a chevron, speech and thought bubbles, a star burst, a heart, a check, a cross, a ring, and a badge, and it also offers the Font Awesome icons ImageGui’s own buttons use. Drag to draw the shape stretched to fit, hold Shift to keep its own proportions, or hold Alt to draw out from the center. Layer > New > Shape > Custom Shape adds the chosen one in the middle of the image.

A custom shape becomes an ordinary path layer with the fill and stroke from the strip, so it stays sharp at any size, the Direct Selection tool can reshape it, and a project holding one opens the same on any computer. Where its outlines overlap, as in the ring or the gaps of an icon, they leave a hole.

To add your own, select a shape or path layer and choose Layer > Shape > Save as Custom Shape, then give it a name. It keeps the outline as the canvas shows it, with any combined shapes merged and any rotation, stretch, or skew applied. Saving under a name that is already taken replaces that shape. Saved shapes belong to ImageGui rather than to a document, so every document can draw them. To remove one, right-click it in the picker.

Layer > Shape > Import Custom Shapes adds the shapes in an SVG file. A file of symbols, such as an icon sheet, gives a shape for each symbol, named by its title; any other file becomes one shape named after the file. Paths, polygons, rectangles, circles, and ellipses are read, with their transforms, and fills, strokes, and colors are left behind. Export Custom Shapes writes your saved shapes to an SVG file, one symbol each, which imports back as the same shapes.

Selecting and masking

A selection decides which part of the image a mask or an adjustment covers. Choose a selection tool from the tool strip over the canvas, where each tool’s name sits under its icon. Under the strip, a row shows the chosen tool’s name and its options, so the canvas stays put as you switch tools. Only a window too narrow for every name makes the names give way to icons alone, shown as tooltips instead:

  • Rectangle Selection (M, press again for Ellipse Selection): drag a rectangle or ellipse.
  • Freehand Selection (L, press again for Polygon Selection): draw freehand or click corners.
  • Color Selection (W, the magic wand in other editors): click a color to select the pixels near it.
  • Quick Selection (W again from Color Selection, sharing its button): paint over part of a subject and the selection grows out to the edges near the stroke. Tolerance decides how far in color from what you painted over it may spread, and Edge how sharp a change in color stops it; [ and ] change the brush’s size. Each stroke adds to a quick selection already there, Alt takes one away, and Deselect starts again. Select > Refine Edge afterward tidies hair and soft edges the stroke found.
  • Pixel (B again from the Brush, sharing its button): paint whole pixels into the selection. See Drawing pixel art.
  • Brush (B): paint into the selection; turn on Erase in its options, hold Alt or press X to erase, and [ and ] change its size. With Color on in its options it paints color onto a paint layer instead; see Painting.
  • Gradient (G): drag a ramp that fades the selection from where you press to where you let go, along the drag (Linear) or out from its start (Radial). Drag either handle afterward to move that end; pressing Shift once the drag has started keeps it to 45 degree steps.

Hold Shift as you start to add to the selection, Alt to subtract, or both to intersect.

The Brush tool’s options row holds its size and hardness, and two settings for how it paints:

  • Flow: how much each dab adds. Dabs build up where they overlap, so a low flow darkens gradually as you paint over the same place, like an airbrush. On a continuous stroke it is the stroke’s strength.
  • Smoothing: the stroke trails the pointer by this many screen pixels on a string, which takes the wobble out of a hand-drawn line.

Its Tip button opens the rest:

  • Spacing: at Continuous the tip is swept along the stroke with no gaps, and doubling back never builds up. Above that it stamps separate dabs this far apart, as a share of the brush’s size.
  • Scatter: how far each dab may stray across the stroke, as a share of the brush’s size. It needs a spacing.
  • Angle and Roundness: below 100% roundness the tip is an ellipse, turned by the angle, for a calligraphic edge. The outline under the pointer shows its shape.

Preset lists saved brushes. Type a name and Save Preset to keep the current size, hardness, and tip settings under it (a name already listed is replaced), or Delete Preset to remove it. Presets are kept in the app’s settings, so every document can use them. The tip settings are written into each stroke, so it still paints the same dabs at any export size.

Symmetry painting

The Brush, the Clone and Spot Removal tools, and Liquify can paint with symmetry. The Symmetry button at the end of each tool’s options (in the Liquify window, under Symmetry) picks how each stroke is repeated:

  • Vertical mirrors it across a vertical axis, left to right.
  • Horizontal mirrors it across a horizontal axis, top to bottom.
  • Both mirrors it across both, so it is painted four times.
  • Radial turns it about a center, from 2 to 32 Segments.

The axes are drawn over the canvas, and the handle where they cross drags them anywhere on it. Hold Shift while dragging to snap the handle to the canvas’s center, or choose Center the Axes. The button is lit while symmetry is on, and the brush outline shows under the pointer and at every copy.

A stroke and its copies are one stroke and one undo step. The stroke records its symmetry in its own frame, so it is redrawn the same at any export size, and it follows its layer when the layer moves. A mirrored clone copies its source mirrored too, and a mirrored twirl turns the other way.

A gradient makes a graduated filter: drag one down over the sky, then Select > Limit Adjustment to Selection on an exposure, and the sky darkens and fades out toward the horizon.

The Select menu holds everything else: All (Ctrl+A), Deselect (Ctrl+D), Invert (Ctrl+Shift+I), Feather (Shift+F6), Modify to grow, shrink, border, or smooth, and Color Range to select by color.

Select > Refine Edge works on the edge of the selection you have. Its View shows the selection under a red overlay, on black, or on white, and the canvas updates as you drag:

  • Radius looks this far either side of the edge and fits it to the selected layer’s own pixels, so a rough outline picks up hair, foliage, or a skyline beside it. Layers with no pixels of their own, such as text and groups, skip it.
  • Smooth rounds off corners and specks, Feather softens the edge, Contrast hardens it again, and Shift Edge moves it outward (positive) or inward (negative).
  • Decontaminate Colors only matters to a mask: it replaces the color along the edge with the color of the nearby fully selected pixels, so a background’s color does not fringe what is kept. Amount sets how much. Exports of a document that uses it are not banded.

OK adds the refinement to the end of the selection’s recipe. Opening Refine Edge again edits it rather than adding a second one, and undo takes it back. Like Modify, it follows the selection into a mask and scales with the layer, so the export refines exactly what the preview showed.

Select > From Layer Transparency, or Ctrl+click on a layer’s thumbnail, selects what that layer draws; Shift adds it to the selection and Alt subtracts it. The selection names the layer rather than copying it, so a mask made from it follows the layer when it moves. Deleting, merging, or ungrouping the layer keeps the mask’s shape, warps and all, as the pixels the layer drew.

Save Selection keeps a selection in the project under a name, and Load Selection brings it back or combines it with the current one.

Masks and limited adjustments

Select > Add Mask hides the selected layer outside the selection. Limit Adjustment to Selection confines one adjustment to it. Both stay editable: load one back with its Edit button, change the selection, and write it back with Replace Mask with Selection.

Graph masks and selections

A texture graph can decide what’s selected or masked, for grunge, worn edges, noise, and anything else a graph can draw. Where the graph is white the layer shows or the pixel is selected, where it’s black it isn’t, and gray is in between. A color graph counts by its brightness.

  • Select > Add Graph Mask… masks the selected layer with the starter graph stretched over the whole layer, and opens it in the texture graph editor, titled with the layer’s name and Mask. It needs no selection. Every edit in the editor is one undo step, a slider drag included, and a layer whose pixels are locked opens it read-only.
  • The mask’s row in the inspector has Edit graph… to open it again, Tile to repeat the graph’s tile across the layer instead of stretching one over it, Tile Size in canvas pixels, and a Seed for a different texture of the same kind. Feather and Invert work as they do on any mask.
  • Select > Texture Graph… makes the active selection a graph stretched over the whole canvas, and opens it in the editor, titled Selection. Add, subtract, intersect, save, and load it like any other selection, or turn it into a mask with Add Mask, and the graph moves with the layer.

A graph mask renders its tile through the same cache as fills, so a fill and a mask drawing the same graph at the same seed render it once, and an export draws it exactly as the canvas does.

Painting

A paint layer holds brush strokes in color. Add one with Layer > New > Paint Layer: it goes above the selected layer, and the Brush tool is chosen, painting color. Selecting a paint layer later switches the Brush to color too, and the Color button at the start of its options switches it back to painting the selection.

While it paints color the Brush’s options add a color swatch and a blend mode beside its size, hardness, flow and tip. The swatch opens the same color popup every other field has. The color’s alpha is the stroke’s opacity, and the blend mode sets how each stroke combines with the strokes beneath it on the layer, so a Multiply stroke darkens what is already painted without touching the layers below. Alt-click the canvas to pick the color shown there, keeping the brush’s opacity. The tip settings, presets, smoothing and symmetry work as they do when painting a selection.

  • Erase (E) chooses the Brush with Erase on, which paints transparency into the layer. B goes back to painting, and X swaps between the two.
  • Painting color while an image layer, or anything other than a paint layer, is selected asks whether to add a paint layer above it. New paint layer above adds one and puts the stroke you just painted on it.
  • A paint layer whose pixels are locked takes no strokes, and the brush’s tooltip says why.

Each stroke is kept as a recipe in the layer’s frame: its path, its tip, and the color and blend it was painted with. Nothing is stored as pixels, so the layer re-renders sharply at any export size, and moving, scaling or warping it carries its strokes along. It takes adjustments, effects, masks, clipping, locks and placement like any other layer. The inspector shows how many strokes it holds, with Clear strokes to start again, and every stroke is one undo step. Layer > Rasterize and Merge Down turn the strokes into pixels when you want them to be.

A long session stays quick: ImageGui keeps the layer rendered up to a recent stroke, so a new stroke, or undoing the last one, draws only what changed rather than every stroke again.

Retouching

Two brushes copy one part of a layer over another, to take out dust, blemishes, and stray wires. Both paint on the selected layer and keep what they paint as a recipe: each stroke is added to a Retouch adjustment at the top of the layer’s stack, or to a new one put there, so the layer’s own pixels are never changed. Switch the adjustment off to see the layer without its retouching, use Remove Last Stroke in the inspector to take a stroke back off, or undo it. Strokes move, scale, and turn with the layer, and an export retouches exactly what the preview showed. A layer whose pixels are locked can’t be retouched.

  • Clone (S, the clone stamp in other editors): Alt-click to set the source, then paint to copy it. With Aligned (the link button) on, the first stroke fixes the distance between the source and the brush and every later stroke keeps it, so the source moves with the brush; off, every stroke starts copying from the source again. A cross shows where the brush is copying from.
  • Spot Removal (J, spot healing in other editors): paint over a blemish. When you let go, ImageGui looks around the stroke for the nearby patch whose surroundings best match the stroke’s, copies it, and shifts its brightness and color so it meets the edge of the stroke, matching both the level and the gradient there.

Both have a size, set with [ and ] as well as the slider, and a hardness: a soft brush blends its edge into the image. A stroke reads the layer as the adjustments beneath its Retouch leave it, and each stroke reads what the strokes before it painted.

Content-Aware Fill

For something too big to paint out, select it and choose Edit > Content-Aware Fill. ImageGui fills the selection on the selected image layer from the rest of the layer: it searches the image for the patches that best continue what surrounds the hole, first on a small copy and then on finer ones, and copies them in, so texture carries on through the fill rather than being smeared across it. Where what it copies is lit a little differently from the edge of the selection, as sky beside a glow is, the copy’s level is bent to meet the edge, so no seam shows.

The dialog previews the fill before you commit to it. Each Seed searches the image its own way, so if the fill copied something you don’t want, Re-roll searches again. To keep it from copying a particular area, save a selection over that area first (Select > Save Selection) and pick it under Don’t copy from. The selection can be feathered or soft: the fill blends in where it is.

OK adds a Content-Aware Fill adjustment at the top of the layer’s stack, holding the selection and the seed, so the layer’s own pixels are never changed. Change the seed from the inspector later, switch the fill off, or undo it. An export fills the same way the preview does, at full size. A layer whose pixels are locked can’t be filled.

The fill looks at the whole layer, so on a very large image it is one of the slower things on a layer’s stack, a second or so on a 24-megapixel photo with a large hole.

Liquify

Filter > Liquify turns the canvas into a brush that pushes the selected image layer’s pixels around, like soft clay. A window opens beside the canvas with five tools:

  • Forward Warp pushes the pixels the way the brush moves.
  • Twirl turns them about the brush’s center while you hold or drag it.
  • Pucker draws them in toward the center, and Bloat swells them out from it.
  • Reconstruct paints the pixels back toward where they started.

Each tool has a size (also [ and ]), a pressure, which is how strongly a dab moves the pixels, and a density, which is how much of the brush moves them fully before the effect fades to its edge. Holding the brush still keeps twirling, puckering, or bloating.

The strokes are a recipe, not pixels: they are added to a Liquify adjustment at the top of the layer’s stack, so you can switch it off, take the last stroke off from the inspector, or undo it. They follow the layer when it moves, and an export redraws them at full size. Restore All takes every stroke off at once, OK closes the window keeping them, and Cancel takes back everything painted since the window opened. A layer whose pixels are locked can’t be liquified.

Displace

The Displace adjustment pushes a layer’s pixels by the values of a texture graph, which is how heat haze, ripples in glass, and fabric folds are made. Add it from the inspector’s Add adjustment list. It starts with soft noise; Edit graph… opens the graph in the editor, and the seed and placement settings below it are the ones a texture fill has.

  • Grayscale mode pushes every pixel the same way, by how bright the graph is there: white pushes the full Horizontal and Vertical amounts, black pushes the opposite way, and middle gray doesn’t move anything.
  • Color mode pushes by the graph’s red channel across and its green channel down, so each pixel can move in a different direction.

The amounts are in canvas pixels, so a preview and a full-size export move the image the same distance. A pixel pushed in from beyond the layer’s edge is transparent, so keep the amounts small near the edges of a photo. Like every adjustment it can be faded, blended, limited to a mask, and switched off.

Vector masks

A vector mask hides a layer outside an outline, and the outline stays sharp at every zoom and export size. Any layer, group, text, fill, or shape can carry one.

  • Draw one: turn on Mask in the Shape or Path tool’s options, then draw. The shape or path becomes the selected layer’s mask instead of a new layer. With a mask already there, Shift, Alt, or the combine mode add to it, cut from it, or intersect with it, just as they do with a shape layer.
  • Take one from a shape layer: Layer > Vector Mask > From Shape Layer uses that layer’s outline where it lies now. The shape layer itself is left as it is.
  • Edit it: the inspector’s Vector mask section, and the same menu, turn it on and off, invert it, and feather its edge. Convert to mask turns it into an ordinary mask you can paint on and refine.

The mask works together with the layer’s other masks: only what all of them show stays visible. It moves, scales, and turns with its layer. The Layers panel shows it beside the layer’s thumbnail. A pixel lock stops any change to the mask, and a position lock stops drawing a new one. A layer in perspective can’t take one.

Geometry: crop, straighten, turn, and resize

These all change where a layer sits rather than its pixels, so they can be undone or changed at any time without losing quality.

Crop, Perspective crop, Draw horizon and Straighten are in the inspector’s Crop and straighten section, at the end of the inspector and folded until you open it. It opens by itself while a crop or a horizon is being drawn.

Crop draws a crop box: drag its corners and edges, lock an aspect ratio if you like, then Apply crop.

The guide drawn over the crop box is picked from its Overlay list, or cycled with O: thirds, the golden ratio, a golden spiral, diagonals, triangles, and a fine grid. Shift+O flips the spiral and the triangles round, and the choice is remembered for the next crop.

Straighten turns the selected layer by an angle. Draw horizon lets you draw a line along something that should be level, and turns the image to match.

Auto, beside the Straighten field, finds the strongest near-level or upright line in the image and levels it in one undo step, which the field can then fine-tune. An image with no clear line is left alone, and the panel says so.

Measuring

The Measure tool (I) drags a line across the canvas. A label beside the line and the Info panel read out its length, its angle (counterclockwise from pointing right, so a line rising to the right is positive), and how far it runs across (dx) and down (dy). Lengths are in the document’s pixels, or in inches, centimeters, or millimeters at the resolution (ppi) you enter beside the unit, since an image carries no resolution of its own.

  • Drag either end to move it; click anywhere else, or press Esc, to clear the line.
  • The ends catch on the canvas edges and center lines, guides, and layer edges while View > Snap is on. Hold Ctrl to place them freely, and Shift to hold the line to 45° steps.
  • Straighten to this line turns the selected layer so the line is level, or upright when it is nearer upright, as one undoable step. The Straighten field carries on from the result.

The line is only for looking: nothing about it is saved, and it goes when the canvas changes size.

Image > Perspective Crop puts four corners on the image. Drag each onto a corner of something photographed at an angle, such as a page or a building’s face, and applying makes that shape the whole canvas, straightened.

The Image menu rotates by quarter and half turns, flips horizontally or vertically, and changes the image’s size:

  • Image Size resamples the whole image to a new size, with the filter it uses chosen beside it.
  • Canvas Size adds or removes canvas around the image without scaling it, and Trim crops to everything visible.
  • Resampling chooses the filter used for the preview and the export alike. Lanczos-3 is the default; nearest keeps hard pixel edges for pixel art.

Saving and exporting

File > Save (Ctrl+S) writes an .imagegui project that keeps your layers, adjustments, and edits, and links to your original images. Save As (Ctrl+Shift+S) saves under a new name, and Save Packaged Copy writes a project that carries its originals inside it, for moving to another machine. A project remembers its selection and straighten angle, so you pick up where you left off.

Each save over a project keeps the one it replaces as a saved version; see Saved versions.

File > Export writes the finished image as PNG, JPEG, WebP, TIFF, TGA, PDF, SVG, OpenEXR, or a layered Photoshop file. An ACEScg image is written as the canvas shows it; see Viewing through ACES. It asks what size to write at (the image’s own size, a percentage, or a long edge in pixels) and, for JPEG and WebP, a quality. Both are remembered for next time.

Beneath the options is a preview of the file: the image as that format and quality will write it, fitted so the whole of it shows, and how big the file will be. Both catch up a moment after you stop moving a control. Actual pixels shows the preview one pixel to one pixel instead, in a window you can drag around, which is where compression shows. Compare with original flips the preview to the image before encoding, which is the quickest way to find the lowest quality that still looks right. An export of up to two megapixels is encoded whole, so its size is exact; a larger one is previewed and measured from a smaller copy, and the size is marked as an estimate.

TIFF is written losslessly, LZW-compressed, so it asks only for a size. A PDF is one page titled after its file: either the image’s size at a chosen number of pixels an inch, or A4, A3, A5, Letter, Legal, or Tabloid turned to match the image, which it fits inside or fills. The image is stored in it as JPEG at the chosen quality, or losslessly.

Replacing files

Exporting to a file that already exists asks first, naming it; Cancel writes nothing. Export Layers, Export As Set and Export Animation ask the same way, once for every file they would replace. The image a document is made from is never replaced: a linked project keeps only your edits and the path of each original, so exporting over one would lose the pixels every edit applies to, in the project and in every saved version of it. Exporting over an original, or over the project’s own file, is refused, and nothing is written.

Dithered gradients

Every export except SVG’s vectors is written at 8 bits a channel, 256 levels, and a smooth gradient that crosses only a few of them would show each as a flat band. So where the image becomes 8 bits, in exports, on the canvas, and when copying to the clipboard, each pixel between two levels takes the upper one as often as it lies toward it, in a fixed pattern finer than a level. Gradient fills, glows, vignettes, and soft skies come out smooth, and a patch averages to the light it was meant to have. A color that already sits exactly on a level, such as an untouched photo’s, is written exactly as it was, so dithering never adds noise to an image that had nothing to lose.

The pattern depends only on where a pixel is, so the same document exports to the same bytes every time, however it is split up to save memory. File > Preferences > Appearance > Dither gradients on 8-bit output turns it off; it is on unless you do. It applies to what leaves ImageGui: exports, batch runs, export sets and the export preview. Images ImageGui keeps inside a project, such as a merged, flattened or pasted layer, a new pattern, or the project’s thumbnail, are never dithered, so the setting can’t change what a project holds. Copying to the clipboard isn’t dithered either, so pasting back what you copied gives the same pixels whatever the setting.

Saving is just as repeatable. Saving an unchanged project writes the same bytes as last time, on any computer, and so does exporting the same PDF again: neither records when it was written.

Exporting as SVG

Name the export .svg to write a vector file. Shape and text layers become real paths: text is converted to outlines, so the file needs none of its fonts, and keeps its colored runs, underlines, and strikethroughs. Fills, strokes with their dashes, caps, joins, and miter limit, opacity, blend modes, and groups become SVG attributes, and solid fill layers become rectangles. Everything else is embedded as a PNG of that layer at the export’s size, cropped to what it covers: photos, gradient and pattern fills, and any layer with adjustments, masks, effects, or a perspective. So is a layer with others clipped to it, drawn together with them. A layer in a blend mode SVG doesn’t have, such as Linear Burn, depends on what is beneath it, so it is drawn as one image with everything below it.

The export options list each layer that will be drawn as an image and why, before anything is written. The size you choose is the size the SVG is shown at; its coordinates stay in canvas pixels. SVG viewers blend translucent layers in sRGB where ImageGui blends in linear light, so translucent edges and blend modes can look slightly different from the canvas.

Exporting as a Photoshop file

Name the export .psd to write a Photoshop file with its layers. Every layer becomes a layer of its own, hidden ones too, with its name, visibility, opacity, blend mode, and clipping, and groups become Photoshop groups, pass-through included. A mask becomes a Photoshop mask you can still paint on, and a vector mask arrives as a pixel mask.

Each layer’s pixels are the layer exactly as it looks here, with its adjustments, effects, perspective, and warp drawn in. Text, shapes, fills, paint, and embedded documents go as pixels too, named for what they were, such as “Title (rasterized text)”. A group with adjustments, effects, a perspective, a warp, or Blend If ranges is drawn as one layer, “(flattened group)”, since a Photoshop group can’t carry them. Where a layer’s effects were drawn from its masked shape, or its mask adds to what the layer shows, the pixels carry the mask and the Photoshop mask is kept, switched off, so it isn’t applied twice. Blend If ranges are left out.

The export options list every layer whose pixels carry something, and why, before anything is written. The file also holds the flattened image, so viewers that don’t read layers still show it, and it is written at the size you choose, up to 30,000 pixels a side. Export As Set can include a PSD output, which is drawn layer by layer and so is counted as a rendering of its own.

File > Export Layers writes each top-level layer, or each selected one, to a file of its own. A document with layer comps can instead write each comp as the whole image.

Exporting OpenEXR files

Choose a name ending in .exr in File > Export to write an OpenEXR file. It is written in float straight from the document, never through an 8-bit image, so a highlight brighter than white leaves ImageGui as bright as it is. The export options ask two more things:

  • Color space: ACES2065-1, the space studios hand EXR files to each other in, unless you choose ACEScg, the space ACES work is graded and composited in, or Linear Rec.709. The file says which in its chromaticities and its color interop id, so the next tool reads it as it was meant (see Working with Blender).
  • Precision: Half float (16-bit), which keeps values up to 65,504 and is what most EXR files hold, or Float (32-bit), which keeps everything at twice the size.

Both are remembered for the next export. Export As Set has an EXR output with the same two choices, and Batch writes EXR too, keeping an EXR image as EXR when it writes each image’s own format.

Exporting an animation

File > Export Animation writes an animated GIF or WebP whose frames are your layer comps, in the order the panel lists them, or each layer at the top of the stack shown on its own, from the bottom up. Layers are used whether their eye is on or not, so a document can keep every frame but one hidden. Choose a file, then:

  • Format: GIF plays everywhere. Each frame gets a palette of its own of up to 256 colors, and a pixel is either clear or solid. WebP keeps every color and soft edges, at the quality you choose.
  • Size: the same choices as Export: the image’s own size, a percentage, or a long edge.
  • Loop forever, or turn it off and say how many times the animation plays.
  • Timing: the field above the frame list sets every frame at once, and each frame’s own field changes just that one. GIF keeps time in hundredths of a second, so its delays round to the nearest 10 ms.

To draw the frames, turn on View > Onion Skin. It shows the frame before the current one tinted red and the frame after it tinted blue, wherever they differ from it, so you can place each drawing against its neighbors; set how strongly they show in the same submenu. Only the canvas shows them, never the image or an export. Previous Frame (Alt+,) and Next Frame (Alt+.) step through the frames, wrapping around at the ends. With comps as frames, each step applies the next comp; with layers, it shows the next layer alone and selects it. Either is one step in the history.

While the options are open, the animation is checked for flashing and the result shown above Export.

Frames are rendered as Export renders the image. Stop in the progress window abandons the export and writes nothing. Batch can’t write animations, since it works on image files, which have neither comps nor layers.

Exporting several files at once

File > Export As Set asks for a folder, then writes every output of a set there in one go. Each output has its own format, quality, size, and a suffix that goes between the image’s name and the extension, so the set that comes with ImageGui writes photo-web.jpg at 2048 pixels on the long edge, photo-print.tif at full size, and photo-thumb.webp at 512. Make new sets, duplicate, rename, and edit them in the same window; Save Sets keeps your changes without exporting. Outputs of the same size share one rendering of the image, and the window says how many renderings the set needs. In File > Batch, choose an export set to write the whole set for every image.

When the image is saved as a project, the list also says whether each file already in the folder is up to date (exported from this project as it stands, with the same format, size, and quality), stale, or not written yet. Export Stale writes only the files that aren’t up to date and leaves the rest alone, so refreshing a set after a small change doesn’t rewrite every file. It is off for an image that isn’t saved as a project, or when Leave out project details in exports is on, since then the files carry nothing to compare.

Batches and the command line

File > Batch runs a set of images, or every image directly inside a folder, through one of your adjustment presets and writes each one to an output folder as PNG, JPEG, WebP, TIFF, TGA, PDF, SVG, or OpenEXR, or as a whole export set. A saved project can be part of a batch too: it is written as it was saved, without the preset, and with Each artboard of a project ticked a project with artboards is written one image per artboard. A batch never writes over one of its images or over an original a project in it links to; those are numbered apart instead. When files it would write are already in the output folder, it asks once before it starts: Replace them all, or Keep both and number the new images apart. The same batch runs without a window from the command line, where files already in the output folder are replaced, so running it again refreshes what it wrote last time:

ImageGui --batch --out web --preset "Golden hour" --size 2048 --format jpg --quality 85 photos/
ImageGui --batch --out delivery --set "Web, print and thumbnail" photos/

--format is one of png, jpg, webp, tif, tga, pdf, svg, or exr; without it each image keeps its own format. A TGA file is written uncompressed unless --tga-compression rle says otherwise. An OpenEXR file is written in ACES2065-1 with half floats unless --exr-space (aces2065-1, acescg, or linear-rec709) or --exr-precision (half or float) says otherwise, and an EXR image written as EXR is worked on in ACEScg, so none of its highlights are clipped on the way through. --size is the long edge in pixels and --percent a percentage; neither enlarges. --scale (2 to 16) writes each image a whole number of times its size, every pixel a hard square. --set names an export set saved in the app (the name’s case doesn’t matter) and writes every output of it for each image. A set chooses its own formats, qualities, and sizes, so it can’t be combined with --format, --quality, --size, --percent, --scale, --exr-space, --exr-precision, or --tga-compression. --artboards each writes each artboard of a project as an image of its own; --artboards whole, the default, writes its whole canvas; --artboard "name" writes just the artboard of that exact name, and fails for a project without one. The command exits with 0 when every image was written, 1 when any failed, and 2 when the command line couldn’t be understood or names a preset or set that isn’t saved.

Batch graphs

When one pass through a preset isn’t enough, a batch can be drawn as a graph. File > Batch Graphs > New Batch Graph opens one: images come in at the Input node, flow left to right along the links through steps such as Apply Preset, Resize, and Watermark, and are written by output nodes such as Export, Export Set, and Save Project, each writing its own files. An output pin linked to several nodes gives each of them its own copy, and an input takes as many links as reach it, so one graph can write a full-size TIFF, a JPEG for the web, and a watermarked proof of every image in one run.

Add node in the editor’s toolbar, or dragging a link into empty space, adds a node; a link dragged from a pin to a pin joins them, and Delete removes what is selected. Each node says on its face what it’s set to, and the panel beside the canvas shows the selected node’s settings. A node that can’t run yet says why on the node itself, and the line above the canvas says whether the whole graph is ready to run.

The editor has an undo history of its own, apart from the image’s: Undo and Redo in its toolbar, or Ctrl+Z and Ctrl+Y while the canvas has the keyboard, never touch the open image, and the editor stays open as images are opened and closed. Save keeps the graph in your library, which File > Batch Graphs lists so it can be opened again; Save to file… writes it as an .imagegui-batch file anywhere, and Open Batch Graph… opens one. Closing the editor with changes unsaved asks whether to save them first.

Previewing a batch graph

A batch graph shows what it will do before you run it. Samples… in the editor takes up to eight images to try the graph on, added one at a time or from a folder, and the graph runs over them without writing anything. Each node then shows how many images reached it and a thumbnail of the first one it sends on, and each output node lists the files it would write, under the names the batch will give them and numbered apart as the batch numbers them. A failure shows on the node it happened at. Hovering over a thumbnail says the size the image would be written at.

The preview runs again whenever a node or link changes; moving a node doesn’t count. The samples are shared by every open editor and kept until ImageGui closes; they aren’t saved with the graph. Because the preview is the batch itself with nothing written, what it shows is what the batch does. Run again in the Samples list runs it over the same images again, for a sample or a watermark that changed on disk.

Making game assets

ImageGui has tools for the images games are built from: sprites, tiles, and the textures an engine reads.

Drawing pixel art

The Pixel tool (the pencil in other editors) paints whole pixels: every pixel it touches is fully covered and none is half covered, so the edges stay hard for sprites, tiles and icons. Press B with the Brush chosen, or click the Pixel button at the start of the Brush’s options. The Pixel tool shares the Brush’s button on the tool strip, which shows whichever of the two you chose last. It paints color onto a paint layer, or into the selection, just as the Brush does, with the same color, blend mode and symmetry, and it keeps a size and an Erase of its own, so switching between the two never resizes either.

  • Size is from 1 to 256 pixels across, and [ and ] change it a pixel at a time. An odd size sits centered on a pixel and an even one on the corner between four.
  • The tip button switches between a square tip and a round one. Round tips are the circles pixel art draws: three pixels across is a plus, five is a square less its corners.
  • Pixel perfect, on by default, takes the doubled pixels out of the corners of a line, as Aseprite does, so a hand-drawn curve stays one pixel thick.
  • Shift-click draws a straight line from where the last stroke ended.
  • Erase (E while the Pixel tool is chosen, or X) clears whole pixels.

Each stroke remembers the pixel grid it was drawn on, so an export at twice or four times the size shows each pixel as a square block rather than a smoothed one, and moving the layer carries the pixels along. Its strokes are saved in project format 14.

Packing channels

Game engines save memory by packing several grayscale maps into the channels of one texture. ImageGui writes those textures from the layers of one project, so the maps stay separate while you work on them and are combined only when they are exported.

Tick Pack channels on an output in File > Export As Set, and the output writes one texture whose red, green, blue, and alpha channels each hold something different. Each channel has a row with a swatch showing what it will hold:

  • Source is a layer or group, a layer comp, or Constant. A layer or group is read whether or not it is visible, with its own adjustments, masks, and effects. A layer comp is read as the whole image that comp shows.
  • Read chooses what of the source goes in the channel: its Luminance, or its own red, green, blue, or alpha.
  • Invert turns the values over, so a roughness layer can be written as smoothness.
  • Value is the constant, for a constant channel. For a layer or comp, it is labelled If missing and is what the channel holds where the source is transparent, and everywhere when the source isn’t in the image.

Fill from a preset sets all four rows for one engine’s layout. The sets that come with ImageGui include one output for each:

Preset Suffix Red Green Blue Alpha
ORM (Unreal) _ORM AO Roughness Metallic 1
Mask map (Unity HDRP) _MaskMap Metallic AO Detail Mask 1 - Roughness
Roughness + metal (glTF) _MetallicRoughness 1 Roughness Metallic 1
ORM (Godot) _orm AO Roughness Metallic 1

A source is found by the layer it was picked from first, so renaming the layer doesn’t lose it, and then by its name, in any case. That is what lets one set, or a batch, write textures for many projects: name the layers AO, Roughness, and Metallic in each, and the presets find them. When a channel’s source isn’t in an image, the channel holds its If missing value and the export still goes ahead, with a note saying which channel had nothing to read. File > Batch and the command line list the same notes.

The channels are written as data. Nothing in View > Display, View > View Transform, the working space, or Dither gradients on 8-bit output reaches them, and the file carries no color profile, so the same project writes the same bytes whatever its color settings. A gray of 128 out of 255 in a layer is 128 in the channel. Packed outputs can be PNG, at 8 or 16 bits a channel, TGA at 8, or OpenEXR, as half or Full float. In the engine, read a packed texture as linear data: Non-Color in Blender, sRGB unticked in Unity, and sRGB off in Unreal.

Drawing with a palette

Every document can carry a palette, an ordered list of up to 256 colors, saved with the project. View > Palette opens it in a panel docked beside Layers.

  • + adds the Brush’s current color, and - removes the swatch you picked.
  • Drag a swatch to reorder the palette. The order matters: it is the order of the indices an indexed PNG writes.
  • Click a swatch to hand its color to the Brush. Its hex code and its index show under the grid.
  • From image… replaces the palette with colors chosen from what the canvas shows, up to the count you ask for, by median cut, as a GIF’s colors are chosen. An image that already has that many colors or fewer keeps exactly the ones it has.
  • Import… and Export… read and write GIMP palettes (.gpl), plain hex lists (.hex), JASC palettes (.pal), and Adobe swatch exchange files (.ase). Exporting picks the format from the file’s extension, and a name without one gets .gpl. An Adobe file’s Lab and CMYK swatches are converted to sRGB as they’re read.

Every change to the palette is one step in History, so Undo takes it back.

Turn on Lock to palette and every color the Brush and the Pixel tool paint with, and a fill layer’s solid color, snaps to the nearest palette entry. Nearest is measured in Oklab, so the snap picks the color that looks closest rather than the one with the closest numbers. The lock keeps each color’s opacity, and it is remembered between sessions. It does nothing while the palette is empty.

Exporting an indexed PNG

When the document has a palette, the export options for a PNG offer Indexed colors in the document’s palette. The file then holds the palette in its own order, and each pixel holds its color’s index, so an engine that looks colors up by index finds them where the palette put them. Pixels less than half opaque are written transparent, through one extra entry after the palette’s own; a palette of 256 colors has no room for it, so an image with transparent pixels needs 255 colors or fewer.

If the image uses a color the palette doesn’t have, the export stops and names a few of them, so nothing is quietly changed. Paint with Lock to palette on to keep the image in its palette, or turn on Dither colors outside the palette, which draws each one as a pattern of the palette’s colors with the same ordered dither the other exports use. Exporting at another size blends neighboring pixels into new colors, so it usually needs dither too. × N, nearest repeats each pixel’s index without blending, so it keeps the palette.

Whole-pixel scaling

Pixel art is drawn small and shipped large. In Export, Export Set, and Batch, the size option × N, nearest writes the image a whole number of times its size, from 2 to 16, with each pixel repeated into an N × N square. Nothing is resampled, so a 32 px sprite exported at × 4 is a 128 px image whose pixels are exactly the sprite’s, edges included. Dithering, when it’s on, is worked out on the original pixels, so its pattern scales with them rather than turning into noise inside each square. A size that would pass 65,536 px on the long edge writes the canvas’s own size, and the export options say so. From the command line, --scale 4 does the same in a batch.

View > Pixel Art Display draws the canvas with nearest sampling above 100%, so pixels are crisp squares at any zoom instead of soft ones until 600%. It changes only what you see; exports and the image are untouched, and the pixel grid still waits for 600%.

Image > Image Size offers the resampling filter beside the new size. When the new size is a whole multiple of the old one, it suggests Nearest so every pixel becomes a hard square, and it warns when Nearest is chosen at a scale that isn’t whole, where some pixels come out wider than others. Changing the filter and the size there is one step to undo.

Working on a normal map

A normal map tells a game or a 3D renderer which way each point of a surface faces, so flat geometry catches light as if it had bumps, grooves, and scratches. Add Normal Map from the inspector’s Add menu and choose its Mode:

  • From Height reads the layer as a height map, white highest, and replaces it with the normal map of that surface. Strength is how tall white stands above black, as a share of the layer’s width, so the result is the same at any size. Turn on Wrap at edges for a tiling texture, so the slopes at each edge are measured against the opposite edge and the normal map tiles too.
  • Normalize brings every normal back to unit length. Use it after painting on a normal map or resizing one, since both leave normals that are too short.
  • Strength makes the bumps stronger or flatter. 1 leaves them as they are, and 0 makes the map flat.
  • Flip Green inverts the green channel. Blender, Godot, Unity, and glTF read OpenGL normal maps, with green pointing up the image; Unreal reads DirectX ones, with green pointing down. ImageGui makes OpenGL normal maps, so add Flip Green when the map is for Unreal.

To lay fine detail, such as a fabric weave or pores, over a normal map, put the detail normal map on a layer above it and choose Normal Detail in the Blend picker. It uses Reoriented Normal Mapping, which bends the detail to follow the surface beneath it rather than averaging the two, so the base’s large shapes and the detail both survive. It’s only meaningful between normal maps, and the picker says so.

A normal map is data rather than color, so these tools never go through color management: the document’s working space and view don’t change what they write. Opacity and coverage still work, so a soft brush selection can fade the detail in and out.

A texture graph has the same tools as nodes: Height to Normal, Normalize, Normal Strength, and Normal Blend, which lays a detail over a base the same way Normal Detail does. A graph that makes a material’s normal map can build it from heights and detail in one place, and they draw the same at every size. See Texture graph fills.

Exporting TGA files

Choose a name ending in .tga in File > Export, or pick TGA in Export Layers, Export As Set, or Batch, to write a Truevision TGA file, which Unity, Unreal, and Godot all import. An image with no transparency is written as 24-bit color, with no alpha channel for an engine to treat as one. An image with any transparency is written as 32-bit color with its alpha as it is, not premultiplied. Rows are stored from the top, which every current reader follows.

The options ask one more thing: Compress (RLE). Run-length encoding makes flat areas, such as masks and UI art, much smaller, and the three engines read it. It’s off unless you turn it on, because an uncompressed file is the one every tool reads. The choice is remembered for the next export, and each TGA output of an export set keeps its own. From the command line, --format tga writes TGA and --tga-compression rle compresses it.

TGA has nowhere to keep metadata, so a TGA export carries no image description and doesn’t say which project or version it came from. Export As Set can’t tell whether a TGA output is up to date, so it always marks one stale, and Export Stale writes it again every time. --check-exports skips TGA files. Export a PNG beside it when you need to trace a file back to its project. ImageGui writes TGA files but can’t open them.

Exporting into a game engine

A project can export itself into a game engine’s folder every time you save it, so the engine reimports the texture and you see the change in the game a moment later. Choose File > Export Targets and click Add folder to pick the folder. A project can have several targets, one per engine or per folder, and they’re saved with the project and can be undone like any other change.

When the folder is in a Unity, Godot, or Unreal project, ImageGui recognizes it from the files the engine keeps there and fills in what that engine needs. Nothing about the engine is saved, and you can change every choice afterwards.

  • Unity imports from Assets/, so a folder outside it is moved to Assets/. The target writes a PNG.
  • Godot imports anything in its project, which it calls res://, and the dialog shows the folder that way. The target writes a PNG, and Write Godot import settings is on, so a normal map, pixel art, or a 9-slice frame is imported the way it needs (see Import settings for Godot).
  • Unreal imports from Content/, so a folder outside it is moved to Content/. The target writes a TGA. Unreal only reimports a file that changes on disk when Auto Reimport is on: turn it on in Editor Preferences > General > Loading & Saving, and check that Content/ is among its directories.

Each target writes an export set, named after the project. Texture (PNG) and Texture (TGA) write one file at the image’s size, and every set from File > Export As Set is offered as well. Subfolder puts the files in a folder under the target: {name} stands for the image’s name, and {artboard} writes each artboard on its own into a folder of its own, so UI/{artboard} gives each button and panel its own texture.

Every save writes every target, whether or not Update exports when this project is saved is on. A file that already matches the project as saved is left alone, so the engine only reimports what changed. TGA files can’t record which project they came from, so a TGA target is written on every save. Writing happens after the save, beside each file and then renamed over it, so the engine never reads half a texture. The status bar says where the save exported, such as Exported to Unity 10:42, with the files listed when you hover it. If a file can’t be written, the save still counts, and ImageGui says which file and why.

Inside a git repository, a target folder in the same repository is saved relative to the project, so the project file is the same in every clone, and a teammate’s save exports into their own copy of the engine’s project.

Exporting a sprite sheet

File > Export Sprite Sheet asks where to write the sheet, then lays every frame out on one image (or several, when they don’t fit) and writes a file beside it that tells a game engine where each frame is. Choose the frames from:

  • Each layer, with each top-level layer as a frame, as Export Animation takes them.
  • Each group’s layers, with each layer inside a top-level group as a frame and each group as an animation of its own, named after the group. Put a walk cycle’s frames in a group called “walk” and an idle loop’s in one called “idle”, and one sheet holds both. Layers outside any group are left out, so a background layer doesn’t become a frame.
  • Each layer comp, with each comp as a frame.
  • Each artboard, with each artboard as a frame.
  • Image files, with each image you add as a frame. Use Add images for single files or Add folder for every PNG, JPEG, WebP, GIF, and BMP image in a folder.

With Same frames as Export Animation ticked, the sheet uses the frames an animation export of the document would, in the same order and with the same frame lengths.

Packed fits the frames together as tightly as it can and keeps the page close to square. Grid puts them in rows in play order, as many columns as you ask for or as square as it can get. Largest page caps the page size, and frames that don’t fit go onto a second page and on. Power of two rounds each page up to a power of two for engines that need it.

Trim transparent edges cuts the empty border off each frame and records how much was cut, so the engine still places the frame where it was. Padding leaves space between frames, and Extrude repeats each frame’s edge pixels outward so filtering doesn’t pull in its neighbors. Premultiplied alpha writes the pixels premultiplied and says so in the file, for engines that expect it.

The metadata can be:

  • TexturePacker JSON (hash), read by Phaser, PixiJS, and Unity’s TexturePacker importer. Frames from groups are also listed by animation, which PixiJS plays as an AnimatedSprite.
  • TexturePacker JSON (array), read by Phaser. PixiJS reads the hash form.
  • libGDX atlas, read by libGDX’s TextureAtlas.
  • Godot resources: an AtlasTexture per frame, SpriteFrames for an AnimatedSprite2D when the frames are an animation, and a TileSet when the sheet is a grid. See Sprite sheets and tile sets.

The same frames with the same options always give the same sheet, byte for byte, so a sheet in a repository only changes when the art does. The preview shows the first page with each frame outlined, and the dialog says what it will write before you export.

Laying out a trim sheet

A trim sheet is a texture of horizontal strips, each repeating across, that a modeler maps long thin faces onto: a band of brushed metal, a row of bolts, a stripe of hazard paint. ImageGui cuts the image into strips with guides.

Turn on View > Rulers and drag guides down from the top ruler wherever one strip ends and the next begins. Then choose View > Trim Sheet Strips. The canvas labels each strip with its name, and the Trim Sheet panel lists them from the top with the rows each one covers and its V range. U always runs from 0 to 1, since every strip spans the whole width. A guide cuts at the pixel row nearest it, so the strips cover every row exactly once.

Type in a strip’s name to rename it. The name is kept on the guide along the strip’s top and saved with the project, and renaming is one undo step. The top strip’s name places a guide on the top edge. A strip you haven’t named is called “Strip” and its number.

Tick V counts up from the bottom for Blender, Unity, and OpenGL, which count V from the bottom of a texture. Leave it clear for Unreal, Godot, and DirectX, which count it from the top.

Export (or File > Export Trim Sheet) writes the image as a PNG, the strips as metadata in the format you pick under Metadata (the same formats as a sprite sheet), and a CSV with one row per strip: name,x,y,width,height,u0,v0,u1,v1, pixels from the top-left, then the UV rectangle with V counted the way the checkbox says. TexturePacker JSON also carries each strip’s UVs. The CSV reads straight into a spreadsheet or a script for Blender’s or Unreal’s trim workflow.

To make every strip tile across, add Make seamless to the layer. On an image with two or more strips, its inspector offers Across only, per strip, which turns off Down. Blending across mixes each row only with itself, so every strip repeats on its own and no strip’s color creeps over a border into the next.

Slicing a UI frame

A button, panel, or dialog frame is usually drawn once at a small size and stretched by the game to fit whatever it holds. 9-slice margins say how: the four corners stay their own size, the top and bottom edges stretch across, the left and right edges stretch down, and the middle fills the rest.

Choose Layer > Slice Margins… and turn on Slice this artboard, or Slice the canvas when the image has no artboards. Each artboard has margins of its own; the list at the top of the panel picks which one you’re editing, and starts at the artboard of the selected layer. New margins start at a quarter of the shorter side. Type the four numbers, in pixels in from each edge, or drag the lines on the canvas:

  • View > Show Slice Margins draws the margins as four green lines across their frame, a color the rulers’ guides never use. With the Move tool, drag a line to move it. It lands on whole pixels, catches on guides, the canvas’s edges, and layers’ edges while View > Snap is on, and never crosses the line opposite it. Each drag is one undo step.
  • The margins belong to the artboard, so they move with it, scale when it’s resized or when you change the image size, and turn and flip with the canvas. A crop that cuts into the middle keeps the margins that are left.

The panel’s Stretch preview draws the frame the way an engine would, at a size you type or drag its corner to. Stretch stretches the edges and middle; Tile repeats them at their own size, as an engine’s tiled draw mode does. The corners never change, whatever the size.

The inspector shows the four numbers while the selected layer’s artboard is sliced, with two buttons:

  • Copy for Unity copies them as L, T, R, B. In Unity, select the sprite, open the Sprite Editor, and type them into Border, in the same order.
  • Copy for Godot offers two choices. NinePatchRect patch margins copies the four patch_margin_left, patch_margin_top, patch_margin_right, and patch_margin_bottom lines. Paste them into the NinePatchRect node in a .tscn file, or type the numbers into the node’s Patch Margin section in the Inspector. StyleBoxTexture texture margins copies the four texture_margin_* lines of a style box, for a .tres or a theme. To have ImageGui write the whole style box, see A UI frame as a Godot style box.

When you export a sliced image, File > Export offers Write the slice margins, which writes button.slice.json beside button.png with the image’s size and its border (left, top, right, and bottom, the names TexturePacker and Unity use) at the size you exported at. For a PNG it also offers Also write a nine-patch, which writes button.9.png: the image with a one-pixel border whose black marks say which rows and columns stretch, the format Android, libGDX, and Defold read. Exporting each artboard writes each one’s own margins beside it.

A sprite sheet carries the margins too. In File > Export Sprite Sheet, each sliced artboard, or each frame of a sliced canvas, writes its margins into the sheet’s metadata: scale9Borders in TexturePacker JSON, which Phaser reads, and split in a libGDX atlas, which gives a NinePatch. When transparent edges are trimmed, the margins lose what the trim cut. Margins are saved in project format 14.

Versions and git

ImageGui keeps every earlier state of your work within reach. There are three kinds:

  • Saved versions, which ImageGui keeps beside a project each time you save over it.
  • Commits, when the project or image is in a git repository.
  • Snapshots from the History panel, which last as long as the image stays open.

The Versions panel lists all three, Compare Images sets any two side by side, and Restore from Version brings back a single layer. Working alone without git, that’s all there is to it: read Saved versions and The Versions panel.

When your projects live in a git repository, ImageGui sets git up to show a project’s changes as text, compare images in a window, and merge projects layer by layer. It commits a project together with the files it depends on, helps you settle a merge’s conflicts, and checks that your exports still match their project. It doesn’t push, pull, or switch branches; use your git client for those. The worked example below runs through the whole cycle once, and the sections after it cover each part in full.

A worked example

A poster lives in a folder of its own: poster.imagegui, with a “Sky” layer that reads the photo sky.jpg beside it and a “Title” text layer above that. An export set writes poster-web.jpg and poster-print.tif into an exports folder. Here it goes into git, gets edited on two branches, is merged, and has its exports brought up to date.

1. Set up the repository

ImageGui works inside a repository but doesn’t make one, so first run git init in the poster’s folder. Then open poster.imagegui and choose File > Git > Set Up This Repository. The window lists the .gitattributes lines and git settings it will write; press Set up. From now on git diff opens projects and images in ImageGui, git log -p shows a project’s changes as text, and git merge merges projects by layer.

Commit .gitattributes with your git client (git add .gitattributes, then git commit -m "Set up ImageGui"), so everyone who clones the repository gets its lines. git doesn’t copy settings into a clone, so each person runs Set Up once on their own clone; the Versions panel offers it when it’s missing.

2. Commit the first version

Choose File > Export As Set and write the set into exports. Then choose File > Git > Commit. It lists poster.imagegui, sky.jpg, and the two exports, each marked new and ticked. Type “First poster” and press Commit. The status bar now shows the branch, main, and puts a dot beside it whenever the project differs from what you last committed.

The next time you open or save the project, ImageGui asks once whether to keep saved versions in this repository. Choose Stop for this repository: commits keep the history now.

3. Edit on two branches

ImageGui doesn’t reload a file that git changes on disk, so close the project before switching branches and open it again after. Close it, and in your git client run git switch -c brighter. Open the project, add an Exposure adjustment to “Sky”, lower the layer’s opacity to 0.8, save, and commit it with File > Git > Commit as “Brighter sky”.

Close the project again, run git switch main, and open it. Change the title’s text, set “Sky” to an opacity of 0.6, save, and commit “New title”. The Versions panel now lists “New title” above “First poster”, each with a line saying what it changed, such as "Title" changed; "Sky" changed.

4. Merge the branches

Close the project and run git merge brighter. ImageGui merges the project by layer: the Exposure adjustment from brighter and the new title from main are both kept. Both branches set the opacity of “Sky”, though, to different values, so that one setting is a conflict:

ImageGui merged poster.imagegui with 1 conflict, keeping ours for each:
  changed both ways: Sky / opacity
Open it in ImageGui to resolve them, or run git mergetool -t imagegui.

git marks the project conflicted and stops before committing the merge.

5. Resolve the conflict

Open poster.imagegui. A banner over the canvas counts one conflict, and the Resolve Conflicts panel lists Sky / opacity with the image under each choice. The project shows 0.6 for now, main’s value. Choose Use Theirs to take 0.8 from brighter, then Mark resolved, which saves the project and runs git add on it. Finish the merge with git commit in your git client.

6. Check the exports

The exports were rendered before any of this, so they no longer match the project. Run:

$ ImageGui --check-exports exports
exports/poster-print.tif: stale since commit 3f2a9c1: Exposure on "Sky" added; "Sky" changed; "Title" changed
exports/poster-web.jpg: stale since commit 3f2a9c1: Exposure on "Sky" added; "Sky" changed; "Title" changed

Each line names the commit the export was made from, “First poster”, and what has changed in the project since. Open File > Export As Set again: it marks both files stale, and Export Stale writes them again. Run the check once more and both lines say up to date, and it exits with 0. Commit the new exports with File > Git > Commit, where only the two exports are ticked, since the project hasn’t changed since the merge.

The same check can run as a pre-commit hook or in CI, so a stale export never gets committed by mistake. See Checking that exports are up to date.

Saved versions

Each time you save over a project, the save it replaces is kept in a folder beside it, named after the project with .versions on the end (Photo.imagegui.versions). File > Preferences > Keep earlier saves sets how many: five unless you change it, and the oldest past that are deleted when you save. None stops keeping new ones without deleting those already kept.

File > Versions lists the earlier saves of the open project in the Versions panel, newest first, each with its thumbnail and the time it was saved. Open as copy opens one as a new, untitled image and leaves the project alone; saving it asks where. Restore replaces the open image with that version as one step, so Ctrl+Z brings back what you had, and the next Save writes it over the project. Versions are earlier saves only: work you haven’t saved is protected by autosave and crash recovery instead.

Right-click a saved version to Name it (“Sent to client”) or Pin it. A pinned version is never deleted to make room, and doesn’t count toward the number Preferences keeps, so five kept and one pinned leaves six. Names and pins are kept in versions.json in the .versions folder, and the project file itself doesn’t change.

Inside a git repository, the versions folder repeats history git already keeps, and shows in git status as untracked files. So the first time you open or save a project git tracks while saved versions are on, ImageGui asks once for that repository, and says how many versions it already holds:

  • Stop for this repository (recommended) keeps no new versions beside any project in the repository. Commit to keep a version instead. Versions already kept stay where they are.
  • Keep them keeps versions as before, and adds *.imagegui.versions/ to the repository’s .git/info/exclude, so git stops listing them. That file belongs to your clone alone, so nothing committed changes.

The question never holds up a save: a save made before you answer keeps a version as it always has. A project in a repository that git doesn’t track yet isn’t asked about. Closing the question without answering leaves the repository unanswered until ImageGui starts again. File > Preferences > In git repositories sets what happens without asking (Ask, Don’t keep saved versions, or Keep saved versions) and lists the repositories you’ve answered for, each with Forget.

Comparing images

File > Compare Images shows two images, or two projects as they render, against each other. It opens with the current file on the after side; choose the before side, or press Last Commit to compare the file with the version git last committed. That reads the committed file through the repository’s filters, so images kept in Git LFS work too.

The images pan and zoom together, and the keys 1 to 4 switch between the four ways of showing them:

  • Side by side puts them next to each other.
  • Swipe lays one over the other with a divider to drag across.
  • Onion skin fades the after image over the before, at the opacity you choose.
  • Difference shows where they differ.

A change of a level or two can’t be seen by eye, so Difference is built to find it. Highlight dims the image to gray and paints every changed pixel magenta, and Exaggerate multiplies each difference, up to 255 times, until the faintest one is at full strength. Absolute shows the difference itself on black instead. Ignore up to treats differences of that many levels or fewer as none, which hides the noise a JPEG re-save leaves. The line under the image counts the changed pixels, gives the largest difference, and says where the changes lie. Images of different sizes are lined up at their top-left corners, and the extra area counts as changed.

When both sides are projects, a Changes list sits beside the images. It lists every difference in the recipe, grouped by layer: a layer added, removed, moved or renamed, an adjustment added or one of its settings changed, an effect, a mask, a guide, a comp. Hover over a change to outline the part of the image it can affect on both sides, and click it to zoom there. When the recipes are the same, the list says so. Any difference left in the pixels then comes from an original image that changed on disk since the project was saved, which the list names, or from how the two were rendered. Layers are followed by the id each project file keeps for them. Files saved before ImageGui kept those ids are matched by layer name instead, and the list says so.

The Versions panel

Every earlier state of the open file is in one Versions panel, newest first, each row with its kind’s icon, a thumbnail, and when it was made:

  • the Working copy, at the top when the image differs from its last save or commit;
  • Saved versions of a project, from its .versions folder (see Saved versions);
  • Commits that changed the file, when it’s in a git repository, with who made each one;
  • Snapshots from the History panel, for as long as the image stays open.

A checkbox for each kind above the list hides or shows it. The panel appears by itself for a file that has saved versions or commits; File > Versions opens it for any file, and View > Versions turns it off and back on. Saving or committing updates it by itself, and Refresh reads it again on demand.

Click a row to choose it, and Ctrl-click a second. Compare opens the two chosen in Compare Images, the older on the left, whatever their kinds: a commit against a snapshot, a saved version against the working copy. With one chosen, Compare sets it against the working copy. Double-click a row to see what it changed since the row below it. Open as copy opens the chosen version as a new, untitled image, and Restore puts it in place of the open image as one step you can undo; both work for saved versions, snapshots, and commits. A commit of a plain image, such as a PNG kept in git, opens or restores with its pixels carried inside the document, so saving it as a project keeps that version rather than pointing back at the file as it is now.

Each row of a project’s versions also says what it changed from the row below it among the kinds shown, such as “Exposure on “Sky” added; Title added“. The summaries are worked out in the background from the two versions’ recipes, without reading their original images, and remembered in ImageGui’s cache folder, so a long history is read once.

Tick This layer only to list just the versions that changed the layer chosen in the Layers panel, each still compared with the version before it. Hovering a layer in the Layers panel shows which version last changed it, such as “Last changed in a1b2c3d by Ada, 3 days ago”, once the panel has found out. Projects saved before version 13 didn’t keep a layer’s identity from one save to the next, so the walk stops at the first of them and the panel says so.

A version that isn’t a file of its own, such as a snapshot or unsaved changes, is written to a temporary folder to be compared or opened, and that folder goes when ImageGui closes. Commits are read through the repository’s filters, so images in Git LFS work, and the panel follows a file back through renames.

Bringing back one layer from a version

Layer > Restore from Version shows an earlier version’s layers, top first as the Layers panel lists them, each with a thumbnail, a mark, and the thumbnail of the image’s layer it was. The mark says whether that layer is the Same as in the version, Differs (it, or something inside it, has changed since), or is Not in image. The window opens on the newest saved version, commit or snapshot; choose another from Version at the top, or right-click a row in the Versions panel and choose Restore Layers to open it on that one.

Choose a layer, then:

  • Replace puts the version’s layer in place of the image’s layer it was, keeping its place in the stack, as one step you can undo. A layer that’s locked, or that the image no longer has, can’t be replaced.
  • Add brings in a copy as a new layer above the selected one, leaving the image’s own as it is.

Either way the layer draws where it did in the version, and brings the original images, fonts and text styles it uses. A version saved before layers kept their ids can only have its layers added.

A layer’s right-click menu in the Layers panel also has Revert to Last Save and Revert to Last Commit, which replace that one layer from the project as last saved or last committed without opening the window. When the layer isn’t in that version, the window opens on it to say so.

Projects in a git repository

A project saved inside a git repository is written so git can follow it. Images in the same repository are recorded by their path relative to the project, so the project opens from any clone wherever it was checked out, and every clone saving the same project writes the same file. Layers, adjustments, masks and fonts keep the same names from one save to the next however you reorder them, so a small edit is a small change, and the project’s description is stored uncompressed so git keeps each save as a small difference rather than a whole new file. Outside a repository a project is saved as before.

Setting up a repository

File > Git > Set Up This Repository makes git open the repository’s projects and images in ImageGui. It lists every line it will write before writing any of it, and writes only when you choose Set up:

  • .gitattributes lines sending projects (*.imagegui diff=imagegui merge=imagegui) and every image type ImageGui opens (*.png diff=imagegui-picture, and so on) to ImageGui. Lines already in the file are left alone, and lines that are already in effect aren’t added again. New ones go at the end, under a # ImageGui comment.
  • The git settings that define those drivers, each naming this copy of ImageGui by its full path: diff.imagegui.command and diff.imagegui-picture.command, so git diff opens the comparison window, diff.imagegui.textconv and diff.imagegui-picture.textconv (with cachetextconv), so git log -p shows a project’s changes as text (see below), and difftool.imagegui.cmd, so git difftool -t imagegui opens the window too, and merge.imagegui.driver, so git merge merges projects by layer (see below). They go in the repository’s own settings unless Write to my global git settings is ticked.
  • With Keep images in Git LFS ticked, git lfs track for the image types. It’s offered only when Git LFS is installed, and only for images: projects are small and stay in plain git, where ImageGui can show their changes. It applies to images added from then on.

Setting up a repository that’s already set up writes nothing. The same setup runs without a window:

ImageGui --git-setup [folder] [--global] [--lfs] [--dry-run]

It sets up the repository the folder is in (the current folder by default), prints every line it writes, and exits with 0, or with 2 when the folder isn’t in a repository or git refused. --dry-run prints the same lines and writes nothing.

git doesn’t copy settings when a repository is cloned, so a clone has the .gitattributes lines but not the drivers they name. When that’s so for the open file, the Versions panel says this copy isn’t set up yet, with a Set up button that opens the same window.

Committing a project

File > Git > Commit commits a project in a git repository together with the files it depends on. It lists the project, each original, each placed project, and the export-set files written from it, each with what git sees of it (new, changed or unchanged) and a tick, on for new and changed files. Type a message and press Commit: ImageGui adds the ticked files and commits them, and nothing else you had staged goes with them. A project with unsaved changes is saved first. When git refuses, for example because no name and email are set or a hook failed, the window shows git’s own words.

An original outside the repository, or one .gitignore leaves out, is listed in red, because whoever clones the repository won’t have it. For one outside, Copy into repository copies it beside the project and relinks every layer that reads it, as one step you can undo. For an ignored one, change .gitignore.

While the project is in a repository, the status bar shows the branch, with a dot when the project differs from its last commit. Clicking it opens Commit. ImageGui commits, but doesn’t push, pull or switch branches; use your git client for those.

Reading what changed in a project, in git

A project is a zip file, so git on its own can only say that it changed. ImageGui --textconv prints a project as text instead, one fact per line, and git can diff that. Set Up This Repository writes these settings for you; by hand they are:

git config --global diff.imagegui.textconv "ImageGui --textconv"
git config --global diff.imagegui.cachetextconv true

Then git log -p, git show, git blame and git diff --no-ext-diff on any file marked diff=imagegui in .gitattributes show the change in words. A changed opacity is one changed line, and an added adjustment is a block of added lines under its layer:

     params
       points [[0, 0], [0.4, 0.55], [1, 1]]
   blend normal
-  opacity 1
+  opacity 0.8
   placement [1, 0, 0, 1, 0, 0]
   source xxh3:96beeeb1e56eca27 "Sky.jpg"
   visible true

The lines list the layers from top to bottom, each with its settings beneath it, then the document’s other lists, then the originals, masks and fonts it uses. A mask or an original is shown as a hash rather than its pixels, so a repainted mask is one changed line, and no line names a folder, so two people’s clones of one repository show the same text. Selecting something, or ImageGui redrawing the thumbnail, changes nothing here.

Images get one line: their format, size and a hash of their pixels, so an image saved again without a changed pixel shows no change at all. A file kept in Git LFS is fetched with git lfs first; without git-lfs installed, the first line says so and the pointer is shown instead.

If diff.imagegui.command is set too, plain git diff opens the comparison window as before and git diff --no-ext-diff shows the text. git runs --textconv once for each version of each file, so it reads only what it prints: it opens no window, looks for no original and loads no font.

Using ImageGui as git’s diff tool for images

ImageGui --diff old.png new.png opens a window showing just the comparison, which closes with Escape. That makes it a difftool for git. Setting up a repository registers it for you; to do it by hand instead, with ImageGui on your PATH, run once:

git config --global difftool.imagegui.cmd 'ImageGui --diff "$LOCAL" "$REMOTE" --name "$MERGED"'

Then git difftool -t imagegui -- art/logo.png compares the working copy of the image with the last commit, and git difftool -t imagegui main -- art/ steps through every changed image under art/ one window at a time. Add git config --global diff.tool imagegui to make it the default for git difftool.

To have plain git diff open images in ImageGui, register it as a diff driver and mark which files use it in the repository’s .gitattributes:

git config --global diff.imagegui.command "ImageGui --diff"
*.png diff=imagegui
*.jpg diff=imagegui
*.imagegui diff=imagegui

git passes its usual seven arguments to the driver and ImageGui reads the two files and the path from them. An added or deleted image is shown against nothing. git log -p uses the driver too when given --ext-diff.

Given --out, the comparison runs without a window and writes the Difference view to a file, for scripts and checks:

ImageGui --diff before.png after.png --out difference.png --exaggerate 16 --tolerance 2

--style is highlight (the default) or absolute, --exaggerate runs from 1 to 255, and --tolerance is the Ignore up to level, from 0 to 254. It prints the same summary the window shows and exits with 0 when the images match within the tolerance, 1 when they differ, and 2 when an image couldn’t be read or the command line couldn’t be understood.

When both files are projects, it first prints the Changes list, one change a line, then the pixel summary. Two projects whose recipes differ exit with 1 even when their pixels match, as after renaming a layer:

Badge: renamed from "Sticker" to "Badge"
Badge: opacity changed from 1 to 0.7
4,812 of 614,400 pixels differ (0.8%), by up to 77 levels, within 192×192 at (720, 48).

Merging projects in git

Without help, git can’t merge two branches that both changed a project: it’s a binary file, so git keeps one side and marks it conflicted. Set Up This Repository makes ImageGui git’s merge driver for projects, and then git merge, git pull, git rebase and git cherry-pick merge them by layer. By hand, the settings are:

git config merge.imagegui.name "ImageGui project merge"
git config merge.imagegui.driver "ImageGui --merge %O %A %B %P"

with merge=imagegui on the projects’ line in .gitattributes.

Each branch is compared with the version both started from, layer by layer and setting by setting:

  • A change only one branch made is kept, and the same change made on both is kept once.
  • Different settings of one layer merge: one branch can raise the exposure while the other renames the layer. So do different layers, and adjustments or effects added on both branches.
  • A layer moved into a group on one branch keeps the other branch’s changes to it, and a layer added on either branch keeps its place beside its neighbors.
  • The masks, originals and fonts either branch added come along.
  • What you had selected and where you were looking are yours.

Some changes can’t both be kept. The same setting changed to two different values, a layer removed on one branch and changed on the other, a layer moved into two different groups, and one list reordered two different ways are conflicts. ImageGui keeps your branch’s choice for each, records the other branch’s in the project, and lists them for git:

ImageGui merged poster.imagegui with 1 conflict, keeping ours for each:
  changed both ways: Sky / opacity
Open it in ImageGui to resolve them, or run git mergetool -t imagegui.

git then marks the file conflicted. The project still opens, showing your branch’s choices, and Resolving merge conflicts settles them. Everything else in it is merged, and its thumbnail is drawn again from the merged image.

Only projects saved by this version of ImageGui can be merged, since an older file has no way to tell which layer on one branch is which on the other. git keeps your branch’s file and marks it conflicted, with a sentence asking you to save both versions in ImageGui and commit before merging. Projects kept in Git LFS merge the same way, with git-lfs installed.

Resolving merge conflicts

A project a merge left conflicts in opens with a banner over the canvas counting them, and the Resolve Conflicts panel open beside it. File > Git > Resolve Conflicts opens the panel again. Each conflict names what it is about, such as Sky / opacity, says what happened to it, and shows the image under each choice:

  • Use Ours keeps your branch’s choice, which is what the project already shows.
  • Use Theirs takes the other branch’s: its value, its order, the group it moved the layer into, or the layer it kept and you removed, which comes back on top. A mask or original only their side used comes back with it.
  • Use Both, for a layer both branches changed, keeps yours and adds a copy of it with their changes just above, named “(theirs)”, so you can compare them or blend them by hand.

Each choice is one step of the history, so Undo brings the conflict back. Choices are saved with the project, and the conflicts left are saved too, so you can stop part way. Once none are left, Mark Resolved saves the project and runs git add on it, and git stops marking it conflicted. If you removed a conflict’s layer since the merge, Use Theirs says it can’t find it; Use Ours still settles it, and you can make their change by hand.

git mergetool does the same from the command line. Set Up This Repository adds the settings:

git config mergetool.imagegui.cmd 'ImageGui --mergetool "$BASE" "$LOCAL" "$REMOTE" "$MERGED"'
git config mergetool.imagegui.trustExitCode true

git mergetool -t imagegui then merges each conflicted project into the working tree’s file and opens it with the panel. When you close ImageGui with no conflicts left in the saved project, git marks the file resolved; with any left, it stays conflicted.

Checking that exports are up to date

An export of a saved project carries where it came from, in the file’s own metadata: the project’s path relative to the export, the project’s fingerprint and the ImageGui version that rendered it. A PNG keeps them in text chunks, JPEG, WebP, TIFF and Photoshop files in XMP, a PDF in its keywords and XMP, and an SVG in its <metadata>. Nothing in them depends on the date, the computer or where the folders are, so exporting the same project twice still writes the same bytes. An image that isn’t saved as a project gets none.

The fingerprint is a hash of the recipe: every layer, adjustment, mask and the hash of every original, with the export’s own format, size, quality and dithering. Selecting something, the thumbnail and saving with another ImageGui version don’t change it.

ImageGui --check-exports reads it back from every export under a folder (the current one when you name none) and prints one line for each:

$ ImageGui --check-exports art/exports
art/exports/poster.jpg: up to date
art/exports/poster.png: stale since commit 3f2a9c1: "Sky" changed
art/exports/banner.png: project missing (../banner.imagegui)
art/exports/logo.png: no provenance

A stale export names the saved version or the commit it was made from when one can be found, and what has changed since. It exits with 0 when every export is up to date and 1 otherwise, so it can run as a pre-commit hook or a CI step. --render also renders each up-to-date export again and compares the pixels, which catches a change in how ImageGui draws rather than in the project; add --tolerance (0 to 254 levels) for a JPEG or WebP, whose compression changes pixels slightly.

To bring stale exports up to date, Export Stale in File > Export As Set writes only the files that aren’t (see Exporting several files at once).

To keep your project’s file name out of what you send, turn on File > Preferences > Leave out project details in exports.

From an export back to its project

Opening an export of a saved project shows a bar over the canvas saying which project it came from, and whether the project has changed since. Open project opens the project instead, so a change goes into the recipe rather than into pixels the next export would replace. Dismiss hides the bar until you open another file. Nothing is shown when the project can’t be found where the export says it is.

When both sides of File > Compare Images are exports of one project, the window says so and offers Compare projects. It finds the version of the project each export was made from (the project as it is now, one of its saved versions, or one of its last 100 commits, whichever has the export’s fingerprint) and compares those two, with the Changes list for the two recipes. When a version can’t be found, the window says which export it was for.

The Blender add-on

ImageGui ships with an add-on for Blender 4.2 and later that sends a texture from Blender to ImageGui and brings it back every time it’s saved. Help > Add-Ons for Other Apps shows where its zip is. To install it, drag the zip into Blender’s window, or in Blender choose Edit > Preferences > Get Extensions, then Install from Disk in the menu at the top right, and pick the zip. The add-on finds ImageGui in the usual install locations by itself. If it can’t, set where ImageGui is in the add-on’s preferences.

The add-on puts two commands in three places: the Image Editor’s Image menu, the right-click menu of a selected Image Texture node in the Shader Editor, and an ImageGui tab in the sidebar (press N) of both editors.

  • Edit in ImageGui opens the texture in ImageGui. When the texture is an export of an ImageGui project, ImageGui opens that project instead, so you edit the layers rather than the flattened image. If the image is packed into the .blend, or has never been saved, Blender offers to save it beside the .blend first, since ImageGui needs a file to open. Changes painted in Blender are saved first too.
  • New Texture in ImageGui asks for a name and a size, makes a blank PNG beside the .blend, puts it in the selected Image Texture node, and opens it in ImageGui. Save the .blend before using it, so the texture has a folder to go in.

While Blender is open, it checks the textures you’ve opened this way about once a second, and reloads any whose file has changed, so saving in ImageGui updates the material in the viewport. It does the same for any texture that sits in a folder with an ImageGui project, which is how an export the project rewrites shows up in Blender. A texture you’ve painted on in Blender and not saved is left alone rather than overwritten; Blender’s system console says so.

Choosing a working space in each app

Work in the same space in both apps, so a color means the same thing on either side:

ImageGui working space Blender working space
ACEScg ACEScg (Blender 5 and later)
Linear sRGB Linear Rec.709

ImageGui chooses in Image > Color Management (see Working in ACES). Blender 5 chooses for each blend file in Render Properties, under Color Management > Working Space. Blender 4 always works in Linear Rec.709, so pair it with a linear sRGB image, or with an ACEScg image whose EXR files you bring across as described below.

Pick ACEScg for renders, lighting, and anything brighter than white, and linear sRGB for textures that only ever need display colors.

Bringing a Blender render into ImageGui

In Blender’s Output Properties, choose OpenEXR as the file format and Float (Half) as its depth, which is what ImageGui holds an EXR in anyway. Use Float (Full) for data such as depth or position, where half loses precision. Leave the codec at ZIP, Blender’s default; ImageGui reads None, RLE, ZIPS, ZIP, and PIZ, but not the lossy DWAA, DWAB, B44, or Pxr24. Save as OpenEXR for one image, or as OpenEXR MultiLayer to bring in every pass as a layer (see Opening a render with its passes).

What happens to the colors depends on the version of Blender:

  • Blender 5 names its working space in every EXR it writes, and ImageGui reads it, so a render opens with the right colors whatever working space or output Color Management you chose.
  • Blender 4 names no color space at all. With Output Properties > Color Management left at Follow Scene, the file holds Linear Rec.709, which is what ImageGui assumes for a file that says nothing, so it opens correctly. If you set it to Override and chose ACEScg or ACES2065-1 as its color space, tell ImageGui: in Preferences > General, set OpenEXR files > Files without a color tag to the same space before opening the file.

Each layer made from a file that names no color space keeps that choice as its own Input Transform, which the project saves. So a project looks the same on every machine, whatever that machine’s preference says. To fix a layer that came in with the wrong one, select it in an ACEScg image and pick the right space under Input Transform in the inspector.

Opening a render with its passes

Save a render from Blender as OpenEXR MultiLayer and File > Open brings in every pass as a layer, whether Blender wrote one part per pass (its default) or all the passes in one part. Each view layer becomes a group, and inside it:

  • Combined sits on top and is the only thing showing, so the image opens looking like the render.
  • Rebuild from passes, hidden, puts Combined back together from the light passes: each component’s direct and indirect light added up and multiplied by its color pass, then diffuse, glossy, transmission, volume, emission, and environment added together, the same sum Cycles and EEVEE make. Hide Combined and show this group, and the image is the same to within the file’s precision, so you can grade the glossy light on its own or turn down the transmission and see the whole image change with it. Rendering with denoising on changes Combined but not the passes, so the rebuild then shows the render before denoising.
  • Other passes, hidden, holds the color passes the rebuild doesn’t use, such as Ambient Occlusion.
  • Data passes, hidden, holds depth, mist, normals, positions, motion vectors, UVs, and the object and material indexes, along with the Cryptomatte ranks. These are numbers rather than colors, so they are read with the Non-Color input transform and never converted: a depth of 7.25 meters is 7.25 in every channel, ready to drive a mask or an adjustment.

Every pass is kept inside the project at the precision the render was saved in, so the project no longer needs the render file. The document works in ACEScg, as any OpenEXR file does. A render from Blender 4, which names no color space, takes Files without a color tag from Preferences, as a single image does.

Selecting by Cryptomatte

Turn on Cryptomatte passes for objects or materials in Blender’s view layer settings, and Select > By Cryptomatte selects with one click. Click an object on the canvas to select it, Shift-click to add another, and Alt-click to take one away; each click is one step of the history. The edges are as soft as the render drew them, so a mask made from the selection doesn’t leave a jagged outline or a halo. With both object and material passes in the file, pick which to click from in the panel. Click Done to put the canvas back.

Placing a render and following new renders

File > Place asks what to bring in from a render with passes. Combined only places the Combined pass as one image layer linked to the file, and that layer follows the file: when Blender writes the render again, the layer takes the new frame within about a second, as one step of the history that undo takes back. Grade the render once, and every new render comes in already graded. Every pass places all the passes as one group, laid out as opening the file lays them out, with the rebuild composed for the document’s working space. A group of passes is a copy and doesn’t follow the file.

Bringing an ImageGui image into Blender

Export as OpenEXR (see Exporting OpenEXR files) and load the file in an Image Texture node, or in Blender’s Image Editor.

  • ACES2065-1, the default, comes into Blender 4 and 5 as ACES2065-1 on its own. This is the safest choice.
  • ACEScg comes into Blender 5 as ACEScg on its own. Blender 4 doesn’t recognize it and shows Linear Rec.709, so set the Image Texture’s Color Space to ACEScg by hand.
  • Linear Rec.709 comes into both as Linear Rec.709.

Every EXR ImageGui writes names its space twice, in its chromaticities and in its color interop id, which is the one Blender 5 reads for spaces other than ACES2065-1.

Textures and data maps

A color texture, such as a base color or albedo map, can be a PNG. Leave its Color Space in Blender at sRGB. Export it from a linear sRGB image, or, from an ACEScg image, set View > View Transform to Un-tone-mapped first, so the PNG holds the image’s colors rather than the tone-mapped look that suits a finished image.

Roughness, metallic, normal, height, and ambient occlusion maps hold numbers rather than colors. In Blender, set the Color Space of each one’s Image Texture node to Non-Color, so Blender reads the values as written instead of converting them. In ImageGui, paint them in a linear sRGB image, where the gray you pick is the number Blender reads: 50% gray, 128 out of 255, is a roughness of 0.5.

Exporting a material

Layer > Export Material…, or Export material… on the graph editor’s toolbar, writes every output of a texture graph to a file of its own, as the maps of one material. It asks for a folder, then for a name, a size (512, 1024, 2048, or 4096 pixels square), and whether the data maps are written with 16 bits a channel, and lists the files before it writes them. Files already in the folder are replaced only when you say so.

Each file is the name and the map’s suffix, the way Blender’s Node Wrangler looks for them: stone_basecolor.png, stone_roughness.png, stone_metallic.png, stone_normal.png, stone_height.png, and stone_ao.png. A Custom map is suffixed with its own name, and two outputs of the same map are numbered apart. In Blender, select a Principled BSDF node, press Ctrl+Shift+T (Add Principled Setup), and pick every file in the folder: Node Wrangler links each one to the right input, with the normal map through a Normal Map node and the height through a Displacement node.

Only base color is an image. It goes to its file through the document’s display and view, as any 8-bit export does, and Blender reads it as sRGB, so in an ACEScg image set View > View Transform to Un-tone-mapped first, as Textures and data maps explains. Every other map is data and is written exactly as the graph computes it, without any color management, so the same graph gives the same bytes whatever the document’s working space or display. Set those maps to Non-Color in Blender, which Node Wrangler does for you. Height is always written with 16 bits, so a displacement has no steps in it, and normal maps are OpenGL style unless the Height to Normal node says otherwise. Each file records where it came from, as every export does; see Checking that exports are up to date.

Editing a texture in ImageGui

A texture exported from a saved project remembers the project it came from, in PNG, JPEG, WebP, TIFF, and OpenEXR files alike. Running ImageGui --edit texture.png opens that project rather than the flattened texture, so you change the recipe, not pixels the next export would write over. When the project is already open, ImageGui comes to the front and keeps it as it is. A file that wasn’t exported from a project, or whose project has moved or been deleted, opens as itself, with the usual bar over the canvas when there is anything to say about where it came from.

Saving a project opened this way writes the texture again, so a program watching the file, such as Blender, picks the change up. This is Update exports when this project is saved, a choice each project makes for itself. It’s in File > Export As Set and in Preferences > Exports, and it is saved with the project and can be undone like any other change. It’s off for a project you open yourself, and on for one opened through --edit until you turn it off.

When it’s on, each save writes again every file exported from the project that no longer matches it: the files of a set written by Export As Set that it would call stale, and the files written by File > Export whose project is still this one. Each is written the way it was before, at the same size, quality, and, for OpenEXR, color space and precision. A file you’ve deleted isn’t written again, and neither is one that a different project has exported to since. The writing happens after the save, so the save itself never waits for it, and each file is written beside the old one and renamed over it, so a program reading it never sees half an image. If a file can’t be written, ImageGui says which and why.

The Godot plugin

ImageGui ships with a plugin for Godot 4.3 and later. Help > Add-Ons for Other Apps shows where its zip is. The plugin adds two commands to the right-click menu of Godot’s FileSystem dock:

It does the same for every image in the folder of a project you’ve opened from Godot, which is how an export the project rewrites on save shows up in Godot, and it brings a new export there into Godot too.

Exporting a material for Godot

When the folder Export Material writes to is inside a Godot project, turn on Godot material in its options to write a StandardMaterial3D beside the maps, as <name>.tres. The options list it after the maps, and ImageGui remembers the choice. Opened in Godot 4.3 or later, the material has each map in its slot:

Map Godot material
Base color Albedo texture
Roughness Roughness texture, read from its red channel
Metallic Metallic texture, read from its red channel, with Metallic at 1
Normal Normal map, with Normal Map turned on
Ambient occlusion Ambient Occlusion texture, with Ambient Occlusion turned on
Height Height map, with Height turned on

A Custom map has no slot and is left out, and when two outputs are the same map the first one is used. Normal maps are OpenGL style, which is what Godot expects, unless the Height to Normal node is set to DirectX. Godot import settings, on by default, tells Godot how to import each map before it first does (see Import settings for Godot).

Pack ORM texture, under Godot material, packs ambient occlusion, roughness and metallic into one texture, <name>_orm.png, and makes the material an ORMMaterial3D that reads it. The channels follow Godot’s ORM layout, the same as the ORM (Godot) preset in channel packing:

Channel Holds When the graph has no such map
Red Ambient occlusion 1, no occlusion
Green Roughness 0.5
Blue Metallic 0

The three maps aren’t written on their own as well, so the options list the packed texture in their place, saying what each channel holds. Each channel holds exactly the values its map’s own file would, written as data at the bit depth the other data maps take. Its import settings read roughness from the green channel for Godot’s roughness limiter. A graph with none of the three maps writes the plain material.

When the folder isn’t in a Godot project, the options are off and the dialog says why. The material is written only once every map has been, so it never names a file that isn’t there.

Sprite sheets and tile sets

Export Sprite Sheet with Godot resources as its metadata writes, beside the page:

  • an AtlasTexture per frame, such as hero-walk_0.tres, cut from the page, with any trimmed edges put back as its margin so the frame keeps its full size;
  • hero-frames.tres, a SpriteFrames resource for an AnimatedSprite2D, when the frames come from layers, comps, or groups. With Each group’s layers, every top-level group is an animation named after it, so a “walk” group and an “idle” group give play("walk") and play("idle"). The other sources play as one animation called default. Every animation loops, and each frame shows for its own length, so a comp’s own delay carries over;
  • hero-tileset.tres, a TileSet for a TileMapLayer, when the sheet is a Grid. Each frame is one tile, the tile size is a cell’s, and padding and extrusion become the atlas source’s separation and margins, so no tile picks up its neighbor. Turn off Trim transparent edges for tiles, so every tile keeps the cell’s full size. A sheet of several pages has an atlas source per page.

Godot 4.3 and later open all three as they are.

Using a project in Godot

With the plugin enabled, an .imagegui project inside a Godot project is imported as a texture, so it can go anywhere an image can: on a sprite, in a material, or in a theme. Godot asks ImageGui to export the project, the same way File > Batch would, and keeps the image it writes. Saving the project in ImageGui imports it again when you return to Godot.

Select the project in Godot’s FileSystem dock and open the Import dock to choose how it’s stored, then press Reimport:

  • Compress > Mode: Lossless (the default) keeps every pixel exactly as ImageGui exports it. Lossy is smaller, at the Lossy Quality you set. VRAM Compressed stores the texture the way the graphics card reads it, which suits 3D textures; it needs Godot 4.5 or later, and earlier versions import the texture lossless instead and say so in the Output panel.
  • Compress > Normal Map: on for a normal map, so it’s compressed in the way normal maps need.
  • Mipmaps > Generate: on for a texture seen at a distance or at an angle, such as one in 3D.
  • Artboard: Whole canvas, or one of the project’s artboards by name, to import that artboard alone. The list comes from the project itself. An artboard whose name has a comma or a colon can’t appear in it; rename it, or export it from ImageGui instead.

Everyone who imports the Godot project needs ImageGui, build servers included, because Godot has no way to read a project on its own. Godot looks for ImageGui where Editor Settings > ImageGui says, then where the IMAGEGUI_PATH environment variable says, then on the system path. Without it, the import fails, naming the project, with “needs ImageGui to import: set its path in Editor Settings > ImageGui.” When some of the people working on the game won’t have ImageGui, export PNG files into the Godot project instead, and keep the .imagegui project outside it, or tell Godot to skip it by putting an empty file named .gdignore in its folder.

A UI frame as a Godot style box

When you export a sliced image into a Godot project, File > Export offers Also write a Godot style box, which writes a StyleBoxTexture beside the image: button.png gets button.tres. ImageGui remembers the choice. Outside a Godot project the option is off, and the dialog says why. It’s offered for the formats Godot imports as textures: PNG, JPEG, WebP, TGA, OpenEXR, BMP, and SVG.

The style box draws the exported image with its Texture Margins set to the slice margins, at the size you exported at, so in Godot it behaves like the stretch preview. Its Axis Stretch follows the preview’s choice: Stretch stretches the edges and middle, and Tile repeats them at their own size. Drop the .tres on a button’s or panel’s style in the Inspector, or into a theme. Exporting each artboard writes each one’s own style box beside it. When the export is a nine-patch itself (button.9.png), the style box leaves the one-pixel marking border out.

Import settings for Godot

Godot keeps how it imports a texture in a .import file beside it, and its defaults suit a photo on a sprite. When ImageGui writes a texture into a Godot project that Godot hasn’t imported yet, it also writes that .import file with the settings the texture needs, and Godot uses them the first time it imports it:

Texture Godot import settings
A normal map: an image with a Normal Map adjustment, or Export Material’s normal map VRAM Compressed, Normal Map on, mipmaps
Pixel art: drawn with the Pixel tool, or exported at a whole multiple (× N, nearest) Lossless, no mipmaps, not compressed for 3D
A 9-slice interface frame Lossless, no mipmaps, not compressed for 3D
Export Material’s base color, metallic, and ambient occlusion VRAM Compressed, mipmaps
Export Material’s roughness VRAM Compressed, mipmaps, with the material’s normal map for Godot’s roughness limiter

Three places write them, each with its own switch:

  • File > Export Targets: Write Godot import settings on each target in a Godot project. It’s on for a target added in a Godot project.
  • Export Material: Godot import settings in its options, on unless you turn it off. ImageGui remembers the choice.
  • File > Export: Write Godot import settings beside exports in File > Preferences, on unless you turn it off.

Undo and history

Edit > Undo (Ctrl+Z) and Redo (Ctrl+Y) step through every change, including each drag. View > History lists the steps by name, marks the one the saved file holds, and jumps to any step in one click.

Undo keeps the pixels of layers you delete, merge, rasterize, or relink, so they can come back. The line at the top of History says how much memory that takes. File > Preferences > History memory limit (1 GB unless you change it) caps it: past the limit, the oldest steps are let go, and the first row becomes the oldest state kept rather than the image as it was opened. The newest step is always kept, however large. If the step a save wrote is let go, the project reads as unsaved until you save again.

New Snapshot, at the top of History, keeps the image as it is now under a name (type one in the field beside it, or leave it empty for Snapshot 1, Snapshot 2, …). Snapshots are listed above the steps. Click one to return to it: that’s one new step, so Ctrl+Z takes you back to where you were, and everything you did after the snapshot stays in the history. Right-click a snapshot to delete it. Snapshots last until you open another image and aren’t saved with the project. They count toward the history memory limit, but they’re the last thing let go: the oldest steps go first. If a snapshot does have to go, a message names it.

Preferences

File > Preferences holds settings that belong to you rather than to a document: how large the interface is drawn and in which colors, how often unsaved work is autosaved, how much memory undo may hold, how many earlier saves of a project are kept, whether a launch reopens what was open, how layer thumbnails are framed, whether Rasterize, Merge Down, and Flatten Image ask first, the clipping overlay’s thresholds, and whether double-clicking an .imagegui project in your file manager opens it in ImageGui.

The General tab groups these under headings, from the preview size to the data folder. Its choices that take a list, such as the autosave interval and the history limit, sit in one column at one width, with their names beside them.

The Appearance tab holds the interface size, the theme, and whether gradients are dithered where they become 8 bits (see Dithered gradients).

Interface size runs from 75% to 200% of the size your display’s DPI gives, which is 100%. It applies at once and is remembered. Menus, panels, the canvas’s handles, and the distance a click can wander before it becomes a drag all grow together, and the canvas’s zoom is left alone. The right column grows with the text in it, so no label in the panels or the inspector is cut off, and the canvas takes what is left. When the canvas is too narrow for the tool strip, the tools drop their names, then shrink, then wrap onto a second row, so every tool stays on screen.

The interface is set in Inter, whose digits are all one width so a value holds still while you drag it. Layer names and other text that holds symbols or emoji draw those too, from a symbol font and an emoji font behind it.

Theme is Dark (the default), Light, or Follow the system, which uses whichever your operating system is set to and changes with it while ImageGui runs. On Linux the system’s setting is read from GNOME’s color-scheme, or the GTK theme’s name. The space around the image, the rulers, and the guides change with the theme; marks drawn over the image itself, such as selection outlines and handles, keep their black and white so they show on any image. Both themes keep text and hints at a contrast of at least 4.5:1 against the panels, and disabled text, graphs, and the keyboard-focus outline at least 3:1. Graphs draw their red, green, and blue darker in the light theme so they show on its white frame.

ImageGui keeps its presets, autosaves, log, and crash reports in one data folder, $XDG_DATA_HOME/ImageGui, or ~/.local/share/ImageGui when that isn’t set, on every platform (on Windows, ~ is your user folder). Preferences names the folder and has a button that opens it. Warnings go to Logs/imagegui.log there as well as the console. Files an earlier version kept in the local application data folder are moved there on the first launch, once, and the log says what moved.

The Performance tab holds the Preview cache: how much of the evaluated image ImageGui keeps so that a drag redraws only the layer and adjustments it changes. Automatic, the default, takes an eighth of your computer’s memory, never less than 512 MB nor more than 4 GB; a busy 24 MP image needs about 700 MB at the 2048 px preview size. The line beneath says how much is held now. A smaller cache is applied at once, letting go of the least recently used results first.

The Keyboard tab rebinds every menu shortcut and tool key: click a shortcut and press the new keys. The menus show whatever is bound, a chord two commands share is flagged on both rows, and Reset or Reset All puts the defaults back.

Keyboard shortcuts

These are the default shortcuts. Shortcuts that act on layers or the canvas are ignored while you are typing in a text field.

Help > Keyboard Shortcuts (Ctrl+/) opens a window listing every command with the shortcut it has now, including any you have changed, grouped like the menus. Type in its search box to find a command by name, by menu, or by its keys, such as ctrl+j. Each row’s Change… button opens Preferences on the Keyboard tab, already listening for the new keys.

Help > Command Palette (Ctrl+Shift+P) finds any command by typing part of its name, such as merge or drop sh, and runs the highlighted one when you press Enter; the arrow keys move the highlight and a click runs a row too. It lists every item of every menu, so adjustments (under Layer > Adjustments), layer effects (switched on and off under Layer > Effects), and panels (the View menu) are all found the same way, along with the tools. Each row shows its shortcut, and a command that can’t run right now stays in the list, grayed, with the reason underneath. Commands whose name starts with what you typed come first, then those with a word starting with it, so sha puts Sharpen and Shape ahead of commands that merely contain the letters.

ImageGui names its tools for what they do, so some differ from other editors: Pixel rather than Pencil, Color Selection rather than Magic Wand, Clone rather than Clone Stamp, Spot Removal rather than Spot Healing, Path rather than Pen, and Sampler rather than Eyedropper.
